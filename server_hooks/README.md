# Серверные хуки SVN-lite

## pre-commit: версии (теги) только для чтения

Версией считается `<X>/tags/<имя>/...`, **только если** в транзакции или в HEAD есть
`<X>/trunk` (то есть `<X>` - проект). Правила:

- создать версию копированием (`svn copy .../trunk .../tags/<имя>`) и папку `<X>/tags` - можно;
- любые добавления, правки (в том числе свойств) и удаления внутри существующей версии - нельзя;
- удалить или заменить саму версию `<X>/tags/<имя>` и папку `<X>/tags` - нельзя
  (`svn delete p/tags`, `svn mv p/tags p/old` отклоняются).

Отказ приходит с сообщением «Версия (тег) только для чтения. Правки делайте в основной
линии или ветке.» Папки `tags` вне проекта (нет `<X>/trunk`) хук не трогает: проект
`g/tags/proj/trunk/...` или `trunk/tags/...` сохраняется как обычно. Граница сегмента
считается от начала пути, поэтому папка «old tags» тегом не является.

**Fail-closed (осознанное решение).** Если `svnlook` не запустился или вернул ошибку (кроме
«путь не найден»), хук отклоняет коммит с текстом «Хук не смог прочитать изменения
(svnlook). Сообщите администратору.» Лучше временно остановить сохранение, чем молча
пропустить правку версии. Путь к `svnlook` в sh-хуке задаётся переменной `SVNLOOK`
(по умолчанию `/usr/bin/svnlook`).

Хук нужен как вторая линия защиты: программа и так не даёт править версии,
но TortoiseSVN и другие клиенты этого не знают.

### Установка

Хук ставится на сервере, в папку `hooks` репозитория: `<репозиторий>/hooks/`.
Нужны команда `svnlook` (идёт вместе с сервером SVN) и права на запись в эту папку.

- **Windows (VisualSVN Server, svnserve):** скопируйте `pre-commit.bat` в
  `<репозиторий>\hooks\` под именем `pre-commit.bat`. В VisualSVN Server папка
  `svnlook.exe` должна быть в `PATH` службы; если нет, впишите полный путь к
  `svnlook` в первой команде файла.
- **Linux:** скопируйте файл `pre-commit` в `<репозиторий>/hooks/pre-commit`
  и выполните `chmod +x <репозиторий>/hooks/pre-commit`.

Ставьте только один вариант под вашу систему. Перезапуск сервера не нужен.

### Проверить на живом сервере

Сообщение отказа в `pre-commit.bat` выводится двумя строками: сначала английской, затем русской
(после `chcp 65001`). `svnserve` может читать вывод хука не в UTF-8, тогда русская строка у
клиента будет искажена, а английская останется читаемой. Проверьте, как текст виден клиенту
на вашем сервере. Кроме того, `.bat` берёт ANSI-кодовую страницу системы из реестра
(`chcp`), чтобы кириллица в путях не искажалась; на службе без консоли это тоже стоит
проверить: создайте проект с кириллическим именем и попробуйте `svn delete .../tags`.

### Проверка

1. Создайте версию: `svn copy <проект>/trunk <проект>/tags/test1 -m "проверка"`. Должно пройти.
2. Измените файл в рабочей копии `tags/test1` и сделайте commit. Должен прийти отказ
   с текстом про «только для чтения».

### Как обойти (администратору)

Хук проверяет все коммиты, включая администраторские. Чтобы что-то поправить
в версии или удалить её, временно переименуйте файл хука (например,
`pre-commit.bat.off`), сделайте нужное и верните имя обратно.

### Ограничения

- Версией считается `<X>/tags/<имя>/` при наличии `<X>/trunk`; проект без trunk защиты не получает.
- Версия, созданная в той же транзакции целиком (например, `svn copy` с правками), правок не блокирует.
- Переименование (перемещение) версии — это удаление и добавление: удаление отклоняется.
