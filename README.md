# SVN-lite

Окно для конструкторов и инженеров: вставить ссылку на проект (или выбрать проект в списке), выбрать папку на компьютере, нажать «Скачать» (подвкладка «Скачать проект» в колонке «Проекты»). Внутри работает `svn.exe` из TortoiseSVN, протокол свой не реализован.

## Что нужно на ПК сотрудника

- Windows 10 или новее.
- TortoiseSVN 1.8+ **с включённой опцией «command line client tools»** (тогда есть `svn.exe`). Если её не включили: запустить установщик TortoiseSVN ещё раз → Modify → включить опцию.
- Доступ к `svn://192.168.11.11` (внутренняя сеть или VPN) и личный логин SVN.
- Python на ПК сотрудника **не нужен**: программа поставляется одним файлом `SVN-lite.exe` (до прототипа файл назывался `SvnHelper.exe`; настройки в `%APPDATA%\SvnHelper` остались прежними).

## Как собрать exe (на машине администратора)

Нужен Python 3.10+. Запустить `packaging\build.bat`. Сборка идёт в своём окружении `out\venv_build`, а не в глобальном Python: туда ставятся PyInstaller точной версии из `requirements-build.txt` и пакет `mcp` из `requirements-mcp.txt`. Если окружение сломано или создано не до конца (его python или pip не запускаются, удалён Python, от которого оно создано), `build.bat` удаляет его и создаёт заново один раз; при неудаче пишет, на каком шаге остановился (`BUILD FAILED: could not …`). Затем он соберёт `out\dist\SVN-lite.exe` по `packaging\SVN-lite.spec` (один файл, без консоли) и `out\dist\svnlite.exe` по `packaging\svnlite.spec` (консольная программа для ИИ-помощника; для неё `build.bat` ставит пакет `mcp` из `requirements-mcp.txt` и останавливается, если он не импортируется). Рядом положит `out\dist\svn_helper.json`, если там его ещё нет. Если в корне проекта лежит `ШПАРГАЛКА.html`, он тоже копируется в `out\dist`. Раздавать сотрудникам эти файлы в одной папке.

## Настройка `svn_helper.json`

Это общий файл администратора: его кладут на сервер (путь задаётся в «Настройки → Параметры») или, для простоты, рядом с `SVN-lite.exe`. Кодировка UTF-8, его правит администратор (кодировка UTF-8, BOM от Блокнота допустим).

| Поле | Значение |
|------|----------|
| `server` | адрес сервера, например `svn://192.168.11.11` |
| `repos` | список репозиториев-корней дерева: корень сервера листингом не получить, поэтому они перечислены здесь |
| `work_dir` | папка для проектов по умолчанию, например `C:\\Проекты_svn` (обратные слеши в JSON удваиваются). Допустимы переменные вида `%USERPROFILE%` |
| `svn_path` | необязательно: полный путь к `svn.exe`. Иначе поиск идёт по PATH, затем в `Program Files\TortoiseSVN\bin` |
| `username`, `password` | необязательно: логин и пароль, с которыми программа входит на сервер сразу. **Пароль хранится в файле открытым текстом**: программа его только читает, никуда не записывает и не пишет в журнал. Если файл общий для всех, оставьте `password` пустым (можно держать `username`): тогда вход идёт через кэш svn или окно входа |
| `filter` | правила проверки содержимого проекта, см. ниже |
| `support` | необязательно: контакт администратора («Иванов И., доб. 123, ivanov@…»). Показывается в окнах ошибок и в «О программе» |
| `latest_version` | необязательно: последняя версия программы, например `1.1.0`. Если она новее запущенной, вверху окна появляется жёлтая полоса «Доступна новая версия» |
| `update_path` | необязательно: где взять новую версию: папка с `SVN-lite.exe` или сам файл `.exe` на сервере (допустимы `%VAR%`). У собранного exe по этому пути идёт автообновление, у запуска из исходников кнопка просто открывает папку |
| `help_path` | необязательно: путь или ссылка на шпаргалку. Пусто: берётся файл `ШПАРГАЛКА.*` из `info_path`, иначе `ШПАРГАЛКА.html` рядом с программой |
| `info_path` | необязательно: папка с документацией на сервере (например `\\192.168.11.11\innotech\Automation\common\INFO`). Программа читает её при запуске и показывает файлы-документы (html, pdf, Word, Excel, текст, картинки; без вложенных папок, не больше 60) в меню «Справка → Документы». Добавили файл в папку: у сотрудников он появится после «Обновить список» или перезапуска. Программы и скрипты в список не попадают |
| `tortoise_installer_path` | необязательно: путь к `TortoiseSVN-*.msi` на сервере (например `\\\\192.168.11.11\\common\\TortoiseSVN.msi`). Если на ПК нет `svn.exe` или TortoiseProc, программа предложит установить TortoiseSVN из этого файла (с «command line client tools», нужно разрешение администратора в окне UAC). Так у всех одна версия |
| `mirrors` | необязательно: папки на диске, которые соответствуют папкам хранилища: `[{"path": "Z:\Проекты_SVN", "repo": "Проекты_SVN"}]`. `repo` — путь от адреса сервера (как в `repos`) или полная ссылка `svn://…`. Тогда в поле ссылки можно вставить путь к папке (`Z:\…` или `\сервер\…`). Свои соответствия задаются в «Параметрах» (поле «Папки на диске → хранилище») и проверяются первыми |
| `templates_root` | необязательно: ссылка на папку шаблонов проектов на сервере, например `svn://192.168.11.11/common/templates` (пример). Каждая подпапка с `template.json` — шаблон. Пусто — окно «Новый проект» пишет «Шаблоны не настроены, обратитесь к администратору». Личными настройками не переопределяется, только общим или рядом лежащим файлом. См. «Проекты из шаблона» |
| `project_folder_format` | необязательно: формат имени главной папки нового проекта, по умолчанию `{{date}}_{{name}}`. Берётся, если в шаблоне нет своего `folder_name`. Пустая строка игнорируется |
| `agent_max_mode` | необязательно: потолок прав ИИ-помощника: `off` (выключен), `read_only` (только чтение, по умолчанию), `write_confirm` (запись только с подтверждением: сотрудник не может включить режим без токена плана), `write` (запись любого вида, если её включил сотрудник или администратор). Действует меньший из файла рядом с программой и общего файла. См. «Доступ для ИИ-агентов» |

Поле `password` из **общего** файла на сервере игнорируется (в журнал пишется предупреждение), и в локальную копию общего файла пароль не сохраняется. Пароль работает только из `svn_helper.json` рядом с программой.

Если файл повреждён или не найден, программа покажет предупреждение и возьмёт значения по умолчанию.

## Фильтр мусора и проверка проекта (секция `filter`)

Перед скачиванием программа просматривает список файлов проекта и применяет правила из `svn_helper.json`:

| Поле | Что делает |
|------|------------|
| `enabled` | `false` отключает всю проверку |
| `skip_junk` | `true`: мусор не остаётся в рабочей папке (после скачивания убирается через `svn update --set-depth exclude`; TortoiseSVN потом не считает его потерянным и не возвращает при Update) |
| `show_report` | показывать отчёт с кнопками «Скачать» / «Отмена», если что-то найдено |
| `junk_extensions` | расширения мусора: `.bak`, `.tmp`, … |
| `junk_names` | точные имена: `Thumbs.db`, `desktop.ini` |
| `junk_prefixes` | начало имени: `~$` (временные файлы Office), `.~lock` |
| `junk_dirs` | имена папок целиком, например `["backup", "Archive"]` |
| `junk_globs` | шаблоны по относительному пути, например `"docs/old/*"` |
| `big_file_mb` | порог «крупного файла» в отчёте |
| `path_warn_length` | порог предупреждения о длинных путях (лимит Windows 260 учитывается всегда) |

Регистр не важен. Важно: мусор всё равно скачивается и затем убирается: SVN не умеет фильтровать при скачивании. Из самого репозитория мусор не удаляется: для этого его нужно убрать на сервере и настроить `global-ignores`.

## Окно: шапка и три колонки

Вверху шапка: «SVN-lite», справа «Вы вошли как ivanov» и кнопка «Сменить пользователя…» (бывшая «Логин и пароль…»), индикатор связи с сервером (клик — «Проверить подключение»). Отдельных вкладок окна нет: «Мои проекты» (открывается первой, повседневная работа) и «Скачать проект» — подвкладки колонки «Проекты» (колонка 2). Вкладки «Ветки и версии» тоже нет: её содержимое во вкладке «Ветки» колонки «Состояние проекта». Внизу окна — панель подсказок (раздел «Подсказки внизу и компактные кнопки»).

Если сервер не отвечает, в панели подсказок внизу окна (жёлтым текстом) появляется «Нет связи с сервером (проверьте VPN)…»: пока нет наведения, совета и результата, и важнее подсказки про проект; уходит при первом ответе сервера. Окно по высоте при этом не меняется. Стартовый размер окна около 1200×720 (на узком экране меньше), минимальный около 900×640. Желтые полосы (новая версия программы, давно занятые файлы) используют цвета из `theme.py`.

## Мои проекты: три колонки

Окно делится на три колонки (раскладка по `docs/PLAN_v3_ui.md`, этап C; состав кнопок по `docs/PLAN_ui_v4.md`):

1. **Кнопки** (слева, не сворачивается). Сверху «Скрыть» (значок глаза: оставляет в колонке одни значки, в таком виде называется «Показать»), затем «Обновить» (значок «⟳»), затем главная кнопка по состоянию проекта: «Разобрать конфликт» (конфликт), «Починить папку» (повреждена), «Восстановить историю» (история на компьютере потеряна, но найдена), «Получить новое (N)» (есть новое или ничего не нужно); у проекта без сервера — «Отправить на сервер…» (папка без истории, история на компьютере и чистая папка, история потеряна и не найдена) или «Продолжить без истории» (если история потеряна). Особая кнопка (разобрать, починить, восстановить) появляется только когда нужна. Дальше «Открыть папку», «Открыть на сервере», «Ещё ▾», внизу «＋ Новый проект…» (обычный стиль, на всю ширину колонки). Название проекта в колонке не повторяется: оно в шапке «Состояние проекта». На всё окно подсвечена одна кнопка; у сохранения подсвечена «Сохранить отмеченное» справа, а если файл изменён, но не занят, — «Занять файл…» на вкладке «Занятые». Сохранение на сервер, занятие файлов и ветки — на вкладках колонки 3, слева их нет.
2. **Проекты** (посередине, сворачивается в полосу). Сверху подвкладки «Мои проекты» и «Скачать проект». На «Мои проекты» вверху «Папка:» с выпадающим списком сохранённых папок, «Выбрать…» и «Найти проекты». Последний пункт списка — «Убрать эту папку из списка» (с диска ничего не удаляется). Выбор другой папки сразу пересобирает список. Ниже поле «Найти проект» (подстрока, без учёта регистра) и таблица. В узком виде — название и строка состояния; когда колонка 3 свёрнута, таблица широкая: «Проект», «Состояние», «Ветка», «Изменён», «Что сделать». Сортировка — щелчком по заголовку «Проект» или «Изменён» (в широком виде). Если при первом запуске в папке для проектов нет ни одного проекта, сразу открывается подвкладка «Скачать проект».
3. **Состояние проекта** (справа, сворачивается в полосу «Состояние»). Шапка: название, цветной статус, «Ветка» и номер сохранения («сохранение № 7»), «что сделать», результат последнего действия. Вкладки (на ярлыках счётчики, где есть): «Изменения», «Новое», «История», «Занятые», «Ветки».

Состояние свёрнутости колонок 2 и 3 сохраняется в `settings.json` (`mine_col2_collapsed`, `mine_col3_collapsed`). Кнопок «Сохранить на сервер», «Занять файл…», «Освободить файл…» и «Ветки и версии» слева больше нет: эти действия на вкладках колонки 3. Двойной щелчок по проекту разворачивает колонку 3 на вкладке главного действия (это путь к сохранению, когда колонка свёрнута). Вкладка «Изменения» открывается сама, когда у выбранного проекта конфликт или несохранённые правки (не во время ввода комментария); если изменённый файл не занят — вкладка «Занятые», где подсвечена «Занять файл…».

Вкладки колонки 3:
- **Изменения** — ваши несохранённые правки: галочки (все отмечены, конфликтные — нет), поле «Что вы сделали?», три шаблона комментария (`commit_templates` в `svn_helper.json`), «Последние ▾» (5 своих комментариев), кнопка «Сохранить отмеченное» (у проекта с историей на компьютере вместо неё «Сохранить у себя»: сохраняются все правки). Проверки до сохранения: пустой комментарий («Напишите, что вы сделали»), ничего не отмечено («Отметьте хотя бы один файл»). Версию (только для просмотра) сохранить нельзя.
- **Новое** — что сохранили коллеги: кто, когда, комментарий, файлы. Подпись: «Ваши файлы не пострадают: придёт только то, что вы не меняли». Читается при открытии вкладки.
- **История** — последние 50 сохранений проекта (кто, когда, комментарий, сколько файлов).
- **Занятые** — ваши занятые файлы (с давностью) и чужие (кто и сколько дней), кнопки «Занять файл…» и «Освободить…» (с выбранными своими строками кнопка называется «Освободить» и освобождает их сразу, а если в каком-то из них есть несохранённые правки, сначала спросит; без выбора откроется список ваших файлов, где файлы с правками не отмечены).
- **Ветки** — список веток и версий выбранного проекта (без своего выбора папки), кнопки «Перейти», «Скачать отдельно», «Новая ветка…», «Зафиксировать версию…», «Перенести правки…» и «Отличия».

Сохранение на сервер делается в самой программе (`svn add` / `svn rm` / `svn commit` на уровне ядра, `SvnClient.commit`). Порядок проверок: версия (только для просмотра) — отказ «Версию менять нельзя, создайте ветку»; занята другая операция над папкой — отказ; на сервере есть новее — вопрос «Получить новое и затем сохранить?» и повтор с тем же списком и комментарием; файл нужно сначала занять — «Занять и сохранить»; конфликт после получения — остановка и «Разобрать конфликт». После успеха: «Сохранено на сервер: N файлов», повторная проверка и, если остались занятые вами неизменённые файлы, вопрос, освободить ли их. Закрытие программы при несохранённых правках спрашивает подтверждение. Дополнительный путь — «Ещё ▾ → Сохранить через TortoiseSVN…» (виден, только если установлен TortoiseSVN).

- **Проверка состояния** (кнопка «⟳», а также сама при открытии подвкладки «Мои проекты» и после «Найти проекты»): «Актуален», «Есть новое на сервере», «Есть несохранённые правки», «Конфликт». Статус берётся с сервера (`svn status -u`).
- **Колонка «Что сделать»** рядом с «Состоянием» подсказывает следующий шаг (например, «Нажмите «Получить новое»»). Эта же строка стоит в карточке, в таблице и в панели подсказок внизу: её считает один модуль (`svnhelper/next_step.py`). Цвет строки: зелёный — актуален, оранжевый — есть новое или ваши правки, красный — конфликт или поломка, серый — обычная папка.
- **Автопроверка**: при открытии вкладки и после «Найти проекты» статус с сервера проверяется сам, не чаще раза в 5 минут на проект; кнопка «⟳» остаётся. Две проверки одновременно не запускаются.
- **Окна TortoiseSVN** (только если найден `TortoiseProc.exe`): «Ещё ▾ → Для опытных» — «История в TortoiseSVN», «Отменить мои правки (TortoiseSVN)…», «Разобрать конфликт в TortoiseSVN» (при конфликте), «Починить папку» (работает и без TortoiseSVN). «Сохранить через TortoiseSVN…» — дополнительный путь сохранения. Откроется окно TortoiseSVN; когда его закроют, статус проекта перепроверяется сам.
- **Занятые файлы**: в подробностях видно «Заняты вами: N» с давностью самого старого и «Файл занят: <кто>, <давность>» для чужих. Если ваши файлы заняты дольше 3 дней, над таблицей появляется напоминание с кнопкой «Показать».
- **Получить новое** (кнопка колонки 1, в скобках число новых): получает свежие изменения с сервера. Ход и «Отмена» — внизу окна. Конфликты не разрешаются сами, программа сообщает о них и предлагает «Разобрать конфликт» (откроется окно выбора версии в программе: «Оставить мою версию» или «Взять версию с сервера»; TortoiseSVN нужен только для «Для опытных»). Фильтр мусора применяется и к новым файлам из «Получить новое». Отмена вызывает `svn cleanup`, копия остаётся рабочей; заблокированную прошлым сбоем копию программа чистит сама.
- **Занять файл…** (только на вкладке «Занятые» колонки 3): выбрать файлы в проекте, и они становятся доступными для записи, а остальным закрываются. Если файл уже занят другим, программа покажет, кто занял и с какого числа (с комментарием, если он есть). Если на сервере более новая версия файла, предложит сначала получить новое. **Освободить…** (Release lock, там же): показывает файлы, занятые вами (с давностью), и снимает блокировку. Чужую блокировку программа не ломает (это делает администратор).
- На подвкладке «Скачать проект» при вводе ссылки показывается, что проект уже скачан.

## Подвкладка «Скачать проект»

Колонка 2 на этой подвкладке — поиск по названию (поле «Найти на сервере») и дерево папок сервера, видное сразу: выбор проекта в нём подставляет ссылку. Колонка 3 называется «Скачивание» и показывает форму из трёх шагов: «1. Какой проект», «2. Куда скачать», «3. Скачать». В шаге 1 вставляется ссылка вида `svn://192.168.11.11/test/projects/.../имя_проекта`. Подходит ссылка с `/trunk` на конце и без, с пробелами и кириллицей (в том числе закодированная `%D0...`), а также путь без адреса сервера (`test/projects/...`). Строка «Что скачать» появляется только у проектов, где есть ветки или версии; под ней одна короткая строка («Создал petrov 19.10 · последнее изменение ivanov 19.10» или «Только для просмотра…»), полная история на вкладке «Ветки» колонки «Состояние проекта». Папка для скачивания выбирается из общего списка папок (тот же, что на «Мои проекты»); новая папка попадает в этот список. Левая колонка кнопок на этой подвкладке скрыта.

Кнопки справа в колонке «Скачивание»: «Скачать» (подсвечена), «Создать проект из этой папки…» (когда путь ведёт к папке, которой ещё нет на сервере), «Удалить недокачанную папку» (после отмены или ошибки). Ход и «Отмена» — внизу окна.

- **Ссылка из буфера обмена**: при запуске и при возврате в окно, если поле пустое, а в буфере ссылка на проект, она подставляется сама («Ссылка вставлена из буфера обмена»).
- **Недавние и избранное**: список под полем ссылки хранит последние 10 скачанных или открытых проектов; кнопка «☆ В избранное» закрепляет ссылку, избранное идёт сверху.
- **Поиск в дереве**: поле «Найти на сервере» ищет по названию среди загруженных узлов и кэша дерева (`%APPDATA%\SvnHelper\tree_cache.json`); клик по результату подставляет ссылку. Узел дерева сначала показывается из кэша (с пометкой «обновляется…»), затем обновляется с сервера.
- **Прогресс**: показывается оставшееся время («осталось ~3 мин») по скорости последних 10 секунд. Ход виден внизу окна и на ярлыке подвкладки («Скачать · 45%»). Если задача шла дольше 30 с, а окно не в фокусе, кнопка в панели задач мигает и звучит сигнал.
- **После скачивания**: окна «Готово» нет. Проект выделяется в «Мои проекты», результат и напоминание про файлы только для чтения — в его карточке. Окно «Скачивание отменено» при отмене осталось.
- **Удаление недокачанной папки**: после отмены или ошибки появляется кнопка «Удалить недокачанную папку» (с подтверждением). Удаляется только папка, которую программа сама создала (или она была пустой) в этом сеансе.
- **Проверка на мусор**: если размер проекта посчитать не удалось, программа явно сообщает «Проверка на мусор пропущена».

## Ветки и версии

Структура проекта на сервере: `<проект>/trunk` (в программе называется «Основная»), `<проект>/branches/<имя>` (ветки), `<проект>/tags/<имя>` (версии: снимок проекта, только для просмотра). Номер сохранения на сервере в программе называется «№» (например, «сохранение № 345»), слово «версия» относится только к снимкам.

**Для пользователя**

- **Скачать ветку или версию**: на подвкладке «Скачать проект» под ссылкой список «Что скачать» (виден, если у проекта есть ветки или версии): «Основная», «Ветка «x» — 19.10, ivanov», «🔒 Версия «y» — 19.10». Ссылка вида `…/branches/имя` или `…/tags/имя` выбирает нужный пункт сразу. Ниже одна строка про ветку: кто создал и кто менял последним. Ветка или версия скачивается в отдельную папку `<проект>__<имя>`; для версии стоит подсказка «только для просмотра», вопросов перед скачиванием нет.
- **Вкладка «Мои проекты»**: колонка «Ветка» («Основная», имя ветки, «🔒 Версия …»); название проекта без суффикса `__ветка`. Для версии выключены «Сохранить отмеченное» и «Занять файл…»; если правки в такой папке всё же появились, программа советует создать из неё ветку. Если прошлое переключение не закончилось, состояние «Переключение не закончено»: откройте вкладку «Ветки» колонки «Состояние проекта» и нажмите «Перейти».
- **Вкладка «Ветки»** (колонка «Состояние проекта»): таблица линий проекта, выбранного в колонке «Проекты» (отдельного выбора папки больше нет). Читается с сервера при открытии вкладки и по «⟳»: «Название» (Основная, ветки, версии; новые сверху; где сейчас папка, там «● вы здесь»), «Создал», «Создана» (подгружаются по мере прокрутки), «Последнее изменение». Под таблицей карточка выбранной линии (кто создал и откуда, кто работал, у ветки ещё занятые файлы; для версии «Только для просмотра.») и кнопки:
  - «Перейти»: папка начинает показывать выбранную линию (Основную, ветку или версию). Неактивна, если папка уже здесь и переключение закончено. Если есть несохранённые правки, программа откажет: сначала сохраните их кнопкой «Сохранить отмеченное» на вкладке «Изменения». Свои занятые файлы программа освобождает сама перед переключением. Если файл открыт в другой программе (Компас, Word, Excel), закройте её и повторите: копию программа приводит в порядок сама.
  - «Отличия»: показывает, чем выбранная ветка отличается от Основной: список файлов с видом изменения (добавлен, изменён, удалён). Загружается в фоне; без связи пишет «Нет связи с сервером» и не показывает ошибку.
  - «Скачать отдельно»: открывает подвкладку «Скачать проект» с этой ссылкой и выбранной линией в «Что скачать».
  - «Новая ветка…» (копия на сервере; галочка «Сразу переключиться» доступна, если нет несохранённых правок) и «Зафиксировать версию…» (снимок проекта, как он сохранён на сервере по последнему сохранению вашей копии; несохранённые правки в версию не входят, имя по умолчанию — сегодняшняя дата, комментарий обязателен). Обе делаются от той линии, на которой сейчас моя папка.
  - «Перенести правки…»: открывает окно TortoiseSVN, слияние и сохранение делаются в нём. Неактивна без TortoiseSVN и для версии.
  - Статус и ход операций показываются внизу окна (панель подсказок). Пока идёт операция, кнопки заблокированы так же, как при «⟳».
- Имя новой ветки или версии проверяется на сервере прямо в окне («Проверяю имя…»); если оно занято, окно остаётся открытым.
- Создание ветки и версии программа делает сама (копирование на сервере), Слияние веток остаётся за TortoiseSVN, сохранение на сервер делается в самой программе.

**Для администратора**: права на запись в `branches/` и `tags/` выдаются как обычно; запрет изменять версии на сервере даёт хук `pre-commit` из `server_hooks/` (установка и проверка описаны в `server_hooks/README.md`). Программа защищает тег только на стороне клиента, сервер остаётся последней линией защиты.

## Подсказки внизу и компактные кнопки

Панель внизу окна говорит, что делает кнопка под курсором, почему кнопка серая и что делать дальше с выбранным проектом. Справа в ней ход долгой операции (получение нового, скачивание) и кнопка «Отмена».

- **Вид → Подсказки внизу**: «Подробно (2 строки)» (по умолчанию), «Коротко (1 строка)», «Только ход работы» (панель видна только на время операции). Выбор запоминается в `settings.json` (`hint_mode`).
- **Высота панели**: за тонкую кромку над панелью её можно тянуть вверх и вниз, строк текста станет столько, сколько помещается; двойной щелчок по кромке (или выбор режима в «Вид») возвращает обычную высоту. Запоминается (`hint_height`).
- **Меню в шапке** («Настройки», «Вид», «Справка») и все их пункты тоже объясняет панель внизу, пока пункт подсвечен.
- Без наведения панель называет одно следующее действие для выбранного проекта, с числами и именами, и говорит, как его сделать (какую кнопку и где), например «У коллег новое: 3 файла. Нажмите «Получить новое» слева…». Карточка «Состояние проекта» говорит то же коротко: строки считает один модуль `svnhelper/next_step.py`. Если у выбранного проекта всё в порядке, панель говорит о самом важном деле другого проекта («В проекте «сушилки»: конфликт…»); важнее всего «Вы не вошли на сервер» и «Папка … не найдена». Когда делать нечего: «Всё сохранено и получено» в режиме «подробно», пусто в «коротко». Пока идёт операция или нет связи, подсказка молчит: говорят ход справа и состояние «Нет связи» (оно в той же панели).
- **Щелчок по тексту подсказки** ведёт к той же кнопке. Если у кнопки своё окно (разобрать конфликт, отправить на сервер, занять файл, выбрать папку; вход — через «⟳»), щелчок нажимает её, с теми же проверками и окнами; серая кнопка не срабатывает. Если кнопка сразу пишет на диск без вопроса («Получить новое», «Починить папку», «Восстановить историю»), щелчок только ставит на неё фокус, нажимаете вы. Для сохранения открывается «Изменения» и курсор встаёт в поле «Что вы сделали?»; для дела другого проекта выбирается его строка. Пока идёт операция, щелчок ничего не делает.
- **Крестик «✕» справа** скрывает подсказку для этого проекта, пока не изменится то, о чём она (например, число файлов). Подсказка о том же проекте меняется не чаще раза в 2 секунды и не мигает.
- Наведение на кнопку, ярлык или строку таблицы заменяет подсказку пояснением; через 150 мс после ухода курсора она возвращается. Фокус с клавиатуры (Tab) тоже даёт пояснение, щелчок мышью — нет (стрелки между ярлыками вкладок пояснение не меняют). Серая кнопка объясняет причину, например: «Сейчас недоступно: идёт получение нового». Тихий сбой без окна («Нужен вход на сервер») виден 15 секунд, итог действия — 10 секунд.
- **Вид → Кнопки → С подписями | Только значки**, а также первая кнопка «Скрыть» (значок глаза) в каждой колонке: слева и справа, в том числе в форме «Скачивание». Только она переключает вид колонки, и у каждой вкладки справа вид свой (меню «Вид → Кнопки» ставит всем сразу). Правая колонка кнопок стоит справа от шапки и вкладок панели «Состояние проекта», а не внутри вкладки; набор кнопок зависит от выбранной вкладки. Стрелки «⟨⟨» в заголовках колонок «Проекты» и «Состояние проекта» (у второй слева от названия) сворачивают колонку, а не меняют вид кнопок. Компактные кнопки квадратные, только со значком; подпись видна во всплывающей подсказке и в панели. Значки — символы шрифта Windows (Segoe MDL2 Assets), картинок в программе нет. Вид запоминается отдельно для левой колонки (`buttons_compact_left`) и для каждой вкладки справа (`buttons_compact_tabs`: `changes`, `locks`, `lines`, `download`; вкладка без записи берёт `buttons_compact_right`).
- В компактном виде у «Получить новое» число новых файлов показано на значке.
- В развёрнутом виде значок стоит слева от подписи, подпись в две строки.
- На экране подсвечена одна кнопка: главное действие по состоянию проекта или «Скачать» на подвкладке «Скачать проект». Так в обоих видах.

## Меню «Вид»: светлая и тёмная тема

«Вид → Как в Windows / Светлая / Тёмная». Тема меняется сразу, без перезапуска, и запоминается в `settings.json` (поле `theme`). «Как в Windows» берёт настройку «Режим приложений» из параметров Windows при запуске. В тёмной теме тёмным становится и заголовок окна (Windows 10 1809+ / 11); полоса меню остаётся системной. Оформление собрано в `svnhelper/theme.py`: палитры `LIGHT` и `DARK`, приглушённый голубой акцент, полужирный основной текст (Segoe UI Semibold).

## Меню «Справка»

- **Шпаргалка**: открывает `help_path` из конфига или `ШПАРГАЛКА.html` рядом с программой (одна страница A4 для сотрудников, печатается). Нет файла — сообщение.
- **Создать ярлык на рабочем столе**: только когда программа запущена как exe, иначе пункт неактивен.
- **О программе**: версия, найденный svn, контакт из `support`.
- **ИИ-помощник…**: что помощнику разрешено сейчас, подписан ли файл его настроек, папки, которые он видит, кнопки копирования команды подключения (Claude Code) и настройки (Claude Desktop), «Открыть журнал действий помощника» (окно журнала, см. ниже) и «Папка с файлами журнала».
- **Журнал действий помощника…**: лента того, что помощник делал в ваших проектах, и кнопки «Отменить это сохранение» и «Вернуть отмену». Подробно: «Доступ для ИИ-агентов», раздел «Журнал действий в окне и отмена».

## Окна ошибок, «Параметры», обновление и запуск

- **Окно ошибки**: понятный текст, контакт из `support` и кнопки «Скопировать отчёт для администратора» (версии, действие, коды `E######`, последние строки вывода svn; пароли маскируются) и «Открыть журнал».
- **Параметры → «Проверить подключение»**: в фоне проверяет svn и список первого корня и отвечает по-человечески («Всё в порядке, вы вошли как …», «Нет связи…», «Неверный пароль…»).
- **Новая версия и автообновление**: если `latest_version` новее текущей, при запуске программа предлагает «Обновить сейчас?», а вверху окна появляется жёлтая полоса с кнопкой «Обновить сейчас». Программа копирует `SVN-lite.exe` из `update_path` рядом с собой, закрывается, маленький скрипт подменяет файл и запускает новую версию (до минуты ждёт, пока старый exe освободится; не вышло — открывает старую). Новую версию программа ищет сама: при запуске и затем **раз в час** (тихо перечитывает общие настройки), а по запросу: «Справка → Проверить обновление программы». Окно «Обновить сейчас?» появляется один раз по каждой новой версии; если в этот момент идёт скачивание или обновление проекта, окно не показывается, а полоса вверху остаётся. Нужны права на запись в папку, где лежит exe. Выпуск версии: поднять `__version__` в `svnhelper/__init__.py`, собрать exe, положить его в `update_path` и только потом поднять `latest_version` в общем `svn_helper.json`.
- **Один экземпляр**: повторный запуск не открывает второе окно, а разворачивает уже открытое (только Windows).

## Настройки в окне программы (кнопка «Сменить пользователя…», меню «Настройки», F12)

Сотрудник просто копирует себе `SVN-lite.exe`, `svn_helper.json` рядом не нужен. Логин и пароль вводить заранее не обязательно: окно входа появится само, когда сервер его потребует (скачивание, обновление, проверка, блокировка файлов).

- **Файл svn_helper.json** — путь к общему файлу на сервере (`\сервер\папка\svn_helper.json`) или ссылка `svn://…/svn_helper.json`. Значение по умолчанию зашито в `svnhelper/config.py` (`DEFAULT_SHARED_CONFIG`): поправьте его перед сборкой на реальный путь. Файл читается при каждом запуске в фоне, окно открывается сразу. Последняя удачно прочитанная копия хранится в `%APPDATA%\SvnHelper\shared_config.json` и используется, когда сервер недоступен. Пункт меню «Обновить общие настройки» перечитывает файл сразу.
- **Вход на сервер** — логин и пароль. Флажок «Запомнить пароль» сохраняет пароль в `settings.json` **в зашифрованном виде (Windows DPAPI)**: расшифровать его может только та же учётная запись на том же ПК. Без флажка пароль живёт только до закрытия программы, а svn не сохраняет его в своём кэше (запускается с `--no-auth-cache`; уже сохранённый кэш он читает по-прежнему). Флажок есть и в окне входа, и в «Параметрах»; по умолчанию он отмечен.
- **Свои значения** — адрес сервера, корни дерева, папка для проектов, путь к `svn.exe`, два флажка фильтра. В `settings.json` попадает только то, что отличается от общих настроек, поэтому правки администратора доходят до всех.

Приоритет (позже важнее): значения по умолчанию → `svn_helper.json` рядом с программой (если есть) → общий файл на сервере → личные настройки.

## Работа в фоне: трей, автозапуск, уведомления

- **Трей.** Значок в области уведомлений (рядом с часами). Меню значка: «Открыть», «Проверить сейчас», «Не беспокоить 2 часа» (повторный выбор снимает паузу), «Выйти». Крестик окна прячет программу в трей, если включено «Сворачивать в трей при закрытии окна» (по умолчанию да; `tray_on_close`). «Выйти» закрывает программу совсем, с вопросом о несохранённых правках. Повторный запуск не открывает второе окно, а показывает уже запущенное.
- **Автозапуск.** «Параметры → Уведомления и фон → Запускать вместе с Windows» (по умолчанию выкл). Пишет значение `SVN-lite` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; запуск из автозапуска идёт с ключом `--tray`: окно скрыто, значок сразу в трее. Если значок создать не удалось, окно показывается и появляется предупреждение.
- **Уведомления.** Программа сама проверяет сервер (в фоне, только если есть связь и программа не занята операцией) и показывает небольшие окошки в **правом нижнем углу** экрана над панелью задач. Они не крадут фокус, складываются стопкой, автоскрываются (через 15 с по умолчанию), у каждого кнопки «Открыть» (покажет программу на нужном проекте и вкладке), «Позже» (откладывает на 1 час) и крестик. Окошки не появляются, пока окно программы открыто и в фокусе. Виды сообщений: новое на сервере (одно на проект, пока число новых файлов не изменилось), несохранённые правки дольше заданного срока (повтор не чаще заданного интервала; проекты с конфликтом и версии не напоминаются), новая версия программы.
- **Настройки «Уведомления и фон»** (Параметры, F12). Всё хранится в `settings.json`, значения по умолчанию в `svnhelper/config.py` (`NOTIFY_DEFAULTS`), применяются без перезапуска:

| Настройка | Варианты, по умолчанию |
|-----------|-------------------------|
| Проверять новое на сервере раз в | 5 / 15 / 30 / 60 минут / только вручную (15 минут; «только вручную» — пункт «Проверить сейчас» в меню значка) |
| Сообщать о новом на сервере | вкл (по умолчанию) |
| Проверять обновления программы / Напоминать об обновлении | вкл; раз в сутки или раз в неделю (сутки) |
| Напоминать сохранить правки, если они не сохранены дольше | 1 / 2 / 4 / 8 часов / не напоминать (4 часа) |
| Напоминать повторно не чаще, чем раз в | 1 / 2 / 4 часа (4 часа) |
| Показывать уведомления | вкл (`notify_enabled`); выкл — окошки не показываются совсем |
| Не беспокоить по часам | выкл; с 18:00 до 09:00 (`notify_quiet_from`, `notify_quiet_to`), «И в субботу с воскресеньем» |
| Сколько секунд показывать окошко | 5 / 15 / 30 / пока не закрою (15 секунд) |
| Показывать только важное | выкл; вкл — только конфликты и несохранённые правки |
| Не уведомлять об этом проекте | флажок по каждому скачанному проекту (`notify_muted`) |
| Запускать вместе с Windows, Сворачивать в трей при закрытии окна | см. выше |
| Проверить уведомления | показывает пробное окошко в правом нижнем углу |
| Вернуть настройки по умолчанию | сбрасывает значения раздела (после «Сохранить») |

Некорректные значения (ноль там, где нельзя, текст вместо числа, неверное время) заменяются на допустимые, а в журнал пишется предупреждение.

## Где что хранится

- `%APPDATA%\SvnHelper\settings.json` — личные настройки из окна «Параметры»: папка, логин, путь к общему файлу, свои значения, зашифрованный пароль (если отмечено «Запомнить»), список папок для проектов (`project_dirs`), последние комментарии к сохранению (`recent_comments`), время последнего открытия проектов, сворачивание колонок 2 и 3, настройки уведомлений и трея. Шаблоны комментариев (`commit_templates`) задаются в `svn_helper.json`.
- `%APPDATA%\SvnHelper\shared_config.json` — копия последнего прочитанного общего файла. **Пароль не сохраняется нигде**, его запоминает сам svn (общий кэш svn и TortoiseSVN).
- `%APPDATA%\SvnHelper\tree_cache.json` — кэш дерева сервера для быстрого открытия узлов и поиска. Недавние проекты, избранное и выбор «Запомнить пароль» лежат в `settings.json`.
- `%APPDATA%\SvnHelper\svn_helper.log` — журнал с сырым выводом svn для разбора проблем. Пароли в журнал не попадают.
- Файлы ИИ-помощника (журнал действий, политика, журналы `svnlite.exe`, замки папок) — в той же папке `%APPDATA%\SvnHelper`, см. «Доступ для ИИ-агентов».

## Как это работает

- Проект на сервере — папка, внутри которой есть подпапка `trunk`. Скачивается именно `trunk`, в папку `<папка для проектов>\<имя проекта>`.
- Сначала программа без явных учётных данных использует кэш svn. Если сервер просит вход, показывается окно логина (до 3 попыток). Пароль передаётся svn через `--password-from-stdin` (svn 1.10+) либо через `--password` (старые версии).
- Перед скачиванием проверяется: путь абсолютный, диск не сетевой, целевая папка пуста, свободного места не меньше 2,2 × размер проекта; путь длиннее 110 символов даёт предупреждение.

## Проекты из шаблона

Новый проект по шаблону: кнопка «＋ Новый проект…» на вкладке «Мои проекты» (левая колонка кнопок, внизу; в колонке «Проекты» она не помещалась при крупном масштабе экрана). Проект собирается из папки шаблона на сервере. Программа меняет только имена папок и файлов: содержимое файлов не подставляется. Замысел и принятые решения — `docs/PLAN_templates.md`, решения по ходу работы — `docs/DECISIONS.md`.

Здесь термины svn (ревизия, trunk, svnadmin) используются намеренно: раздел для администратора и разработчика. Тексты для сотрудников — в `ШПАРГАЛКА.html`, раздел «В. Новый проект из шаблона».

### Настройка

Два поля в `svn_helper.json` (см. таблицу выше):

```json
"templates_root": "svn://192.168.11.11/common/templates",
"project_folder_format": "{{date}}_{{name}}"
```

(фрагмент; адрес `templates_root` — пример.)

- `templates_root` задаётся только в общем файле или в файле рядом с программой. Личные настройки его не переопределяют. Список шаблонов читается при открытии окна в фоне; без связи — из шаблонов, уже сохранённых на компьютере.
- `project_folder_format` — формат имени главной папки. Если в шаблоне есть `folder_name`, он важнее.
- Создавать проект может любой, у кого есть запись в выбранном месте сервера (authz). Отдельного списка нет: ограничение «кто может создавать» (`project_creators`) в первой версии не сделано.

### Шаблон на сервере

Шаблон — папка внутри `templates_root` с файлом `template.json` в корне. Подпапки без `template.json` шаблонами не считаются. Версия шаблона — ревизия, в которой папка менялась последний раз. Файл `template.json` в проект не копируется.

Уже созданные проекты при изменении шаблона не меняются.

### `template.json`

Пример (шаблон «Электроника: проект»):

```json
{
  "format": 1,
  "title": "Электроника: проект",
  "description": "Папки, спецификация, схемы",
  "folder_name": "{{date}}_{{name}}",
  "parent": "konstruktor/projects",
  "fields": [
    {"id": "date", "label": "Дата", "default": "{{today:yyMMdd}}"},
    {"id": "name", "label": "Название", "required": true, "hint": "например, отбраковщик вафель"}
  ],
  "renames": {
    "README.txt": "README_{{folder}}.txt",
    "docs/Specification/Шаблон каталог спецификация электроника.xlsx": "{{folder}}_спецификация.xlsx"
  }
}
```

| Поле | Обязательно | Что значит |
|------|-------------|------------|
| `format` | да | `1`. Шаблон с более новым форматом программа не читает: просит обновить программу |
| `title` | нет | название в списке шаблонов (по умолчанию имя папки шаблона) |
| `description` | нет | описание под списком |
| `folder_name` | нет | формат имени главной папки; по умолчанию `project_folder_format` из `svn_helper.json` |
| `parent` | нет | место на сервере без адреса, например `konstruktor/projects`. Должно начинаться с одного из корней `repos`. Без `parent` место выбирает человек в окне |
| `fields` | нет | поля диалога. Поля `date` (Дата, по умолчанию `{{today:yyMMdd}}`) и `name` (Название, обязательное) есть всегда; шаблон может их переопределить |
| `renames` | нет | переименование файлов и папок внутри шаблона, см. «Правила renames» |

Каждое поле из `fields`: `id` (только буквы, цифры и `_`; не `folder`, `author`, `today`; не повторяться), `label` (подпись), `default` (значение по умолчанию; можно `{{author}}` и `{{today:маска}}`), `required` (`true`/`false`), `hint` (подсказка под полем). Значение поля доступно как `{{id}}`. Поля только текстовые: выпадающих списков и проверки по маске в первой версии нет.

### `project.json`

Лежит в корне главной папки проекта. Создаётся при создании проекта из шаблона:

```json
{
  "format": 1,
  "name": "отбраковщик вафель",
  "folder": "261028_отбраковщик вафель",
  "created": "2026-10-28T14:05:00",
  "author": "ivanov",
  "template": {"id": "electronics", "title": "Электроника: проект", "revision": 412},
  "fields": {"date": "261028", "name": "отбраковщик вафель"},
  "svn": null,
  "links": {}
}
```

- `name`, `template` — программа читает их для списка «Мои проекты»; остальное записывается.
- `author` — логин svn, если его знает программа, иначе имя пользователя Windows.
- `svn` — `null`, пока проект не на сервере. После отправки там `{"url": "...", "published": "..."}`. Это справочное поле: решения принимаются по `svn info` (есть ли `.svn` и адрес `svn://`), а не по файлу, потому что файл можно скопировать вместе с чужой папкой.
- `links` — заготовка под ссылки (чат, доска задач); программа её пока не читает.
- Путь к локальной истории в файл не пишется: файл уходит на сервер, а путь `C:\Users\…` там бессмыслен (см. `settings.json` ниже).
- Файл пишется в UTF-8. Неизвестные поля сохраняются при перезаписи. Битый файл программа не читает и пишет об этом в журнал. Более новый `format` читается с предупреждением.

### Поля и плейсхолдеры

| Подстановка | Что это | Где можно |
|-------------|---------|-----------|
| `{{id}}` | значение поля (`name`, `date` и свои из `fields`) | `folder_name`, `renames`, значения полей |
| `{{folder}}` | итоговое имя главной папки | только `renames` (в `folder_name` нельзя: папка не может ссылаться на саму себя) |
| `{{author}}` | автор, как в `project.json` | `folder_name`, `renames`, `default` |
| `{{today:маска}}` | сегодняшняя дата по маске (на момент создания) | `folder_name`, `renames`, `default` полей |

Значения `default` полей не могут ссылаться на другие поля: в них доступны только `{{author}}` и `{{today:…}}`.

Маски дат — только четыре токена, остальные символы остаются как есть:

| Токен | Пример (2 ноября 2026) |
|-------|------------------------|
| `yyyy` | `2026` |
| `yy` | `26` |
| `MM` | `11` (месяц) |
| `dd` | `02` |

`yyMMdd` даёт `261102`, `yyyy-MM-dd` даёт `2026-11-02`. Запрещено: `mm` (путают с минутами), любые другие буквы (в том числе коды `strftime` вида `%Y`), `/` и `\`. Ошибка в маске — отказ при загрузке шаблона с сообщением администратору.

Формат имени главной папки по умолчанию: `{{date}}_{{name}}` → `261102_отбраковщик вафель`.

### Правила `renames`

- Ключ — путь от корня шаблона через `/` (обратный слэш тоже принимается). Путь должен существовать в шаблоне. Сравнение без учёта регистра; в программе используется написание из шаблона. Пути — старые имена, даже если папка переименовывается.
- Значение — только имя, без `/` и `\`. Может содержать подстановки. Проверяется как имя для Windows: не пустое, без символов `: * ? " < > |` и управляющих, не начинается с пробела, не заканчивается пробелом или точкой, не `CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9` (в том числе с расширением, например `CON.txt`), не длиннее 255 символов.
- Переименовывать можно и файлы, и папки.
- Два источника в одно имя в одной папке (без учёта регистра) — ошибка. Новое имя, совпавшее с соседом, который не переименовывается, — тоже ошибка.
- Порядок: от самых глубоких путей к верхним. Внутри одного уровня имена меняются через временные имена, поэтому цепочки вида `a → b`, `b → c` не мешают друг другу.

Пример: `"README.txt": "README_{{folder}}.txt"` при папке `261102_отбраковщик вафель` даёт `README_261102_отбраковщик вафель.txt`.

### Ошибки в шаблоне (для администратора)

Программа не исправляет шаблон молча: ошибка показывается по-русски и начинается с «В template.json …» или «Шаблон настроен неверно». Типичные причины:

- неизвестная подстановка `{{x}}`, `{{today}}` без маски;
- ключ `renames`, которого нет в шаблоне;
- два источника в одно имя (без учёта регистра);
- `/` или `\` в новом имени или в значении поля;
- `{{folder}}` внутри `folder_name`;
- `id` поля совпадает со встроенным (`folder`, `author`, `today`) или повторяется;
- `parent` не начинается с корня из `repos`;
- битый JSON, неизвестный `format`, шаблон для более новой программы;
- при подстановке получилось недопустимое имя (проверяется пример подстановки).

### Длина имён и путей

- Имя главной папки на сервере — не длиннее 80 символов (`server.MAX_LINE_NAME`), без `/ \ : * ? " < > |`, не начинается и не заканчивается точкой.
- Длина путей считается для итоговой папки и для временной папки сборки (`.<имя>.creating`, на 10 символов длиннее): реальный предел чуть ниже.
  - больше `filter.path_warn_length` (по умолчанию 200): предупреждение, проект создаётся;
  - файлы: 260 и больше — отказ (лимит Windows, `audit.WINDOWS_PATH_LIMIT`);
  - папки: 248 и больше — отказ.

### Кэш шаблонов

- Где: `%APPDATA%\SvnHelper\templates_cache`. Если `%APPDATA%\SvnHelper` лежит в Roaming (профиль ходит по сети), кэш кладётся в `%LOCALAPPDATA%\SvnHelper\templates_cache`.
- Структура: `<8 символов>\meta.json` (id, название, ревизия, дата скачивания) и `<8 символов>\r<ревизия>\files` (копия шаблона). Версия в кэше после записи не меняется; новая версия кладётся рядом, и указатель в `meta.json` переключается одной заменой файла.
- Если ревизия в кэше совпадает с ревизией на сервере, копия не скачивается.
- При запуске (если есть связь) кэш прогревается. Старые версии и временные папки старше суток удаляются.
- Без связи шаблон берётся из кэша. Если его в кэше нет, программа пишет: «Нет связи с сервером, а этот шаблон на компьютер ещё не скачивался…».

### Журнал задач (`create_jobs`)

- Где: `%APPDATA%\SvnHelper\create_jobs\<id>.json` (`publish.default_jobs_dir()`, с учётом `SVNLITE_DATA_DIR`).
- Один файл на незаконченную операцию. Поле `kind`: `create_local` (создание проекта, в том числе «сразу на сервер»), `publish` (отправка на сервер), `local_history` (включение истории).
- Файл пишется после каждого шага и удаляется при успешном завершении. Стадии по порядку: создание — `building` → `uploading` → `download`; отправка — `started` → `source_ready` → `uploading` → `uploaded` → `binding` → `bound`; история — `started` → `repo_created` → `layout_created` → `imported` → `checking_out` → `checked_out`.
- Файлы содержат пути папок и логин автора; пароли в них не попадают.
- При запуске программы журнал разбирается: `app._recover_new_projects` (создание и история: убрать `.<имя>.creating`, при стадии `uploading` проверить сервер, при стадии `download` убрать недокачанную папку) и `app._recover_publish_jobs` (отправка: нужна связь с сервером; без неё журнал остаётся до следующего запуска). Пользователь при этом видит предложение «Завершить отправку» или «Убрать недоделанное».

### Локальная история (`.svnlite`)

- Где: `<папка проектов>\.svnlite\history\<8 символов>` (`localrepo.history_root`). Папка `.svnlite` скрытая, внутри неё `README.txt` с пояснением. История всегда на том же диске, что и папка проекта.
- Адрес истории записывается в `settings.json` → `local_histories`: ключ — путь к папке проекта, значение — путь к истории. В `project.json` его нет.
- Создаётся при создании проекта, если найден `svnadmin.exe`. Поиск: рядом с найденным `svn.exe` (`config.find_svnadmin`): сначала `svn_path` из настроек, затем `PATH`, затем `Program Files\TortoiseSVN\bin`. Обычно `svnadmin.exe` лежит в той же папке, что `svn.exe`, в TortoiseSVN.
- **Без `svnadmin.exe` история не создаётся, ошибки нет:** проект создаётся без истории, кнопка «Сохранить у себя» не появляется.
- Если включить историю не вышло (например, сбой `svnadmin create`), проект остаётся на месте, без истории; пользователю говорится, что прежние сохранения не будут храниться.
- Включение: `svnadmin create` → `svn mkdir` папок `trunk`, `branches`, `tags` по адресу `file:///` → `svn import` в `trunk` (мусор отсеивается теми же правилами, что и при отправке) → `svn checkout --force` в папку проекта. Файлы на диске при привязке не перезаписываются.
- Сбой или остановка: созданные история и `.svn` удаляются, папка проекта остаётся как была. Если убрать не вышло, уборку повторяет `recover_jobs` при запуске.
- Работа с историей: «Сохранить у себя» (все правки, включая новые файлы, в историю на компьютере; комментарий необязателен). Ветки и версии локально не делаются. Перенос истории на сервер не делается.
- После отправки на сервер история остаётся архивом. Удаляется только явно: «Ещё ▾ → Удалить прежние сохранения на этом компьютере…» (с подтверждением). Пока папка привязана к этой истории, удалить её нельзя.
- История пропала: состояние «История на этом компьютере потеряна». Если папку проектов переименовали или перенесли, хранилище лежит рядом (`<папка проектов>\.svnlite\history\*`, а также в других папках проектов и по путям из `settings.json`): программа находит его по uuid (`localrepo.find_history`), главная кнопка карточки — «Восстановить историю» (`localrepo.restore_history`: `svn relocate` на новый адрес `file:///`, запись в `settings.json` переписывается). Хранилища нет совсем — «История этого проекта на компьютере не найдена», главной становится «Отправить на сервер…» (отправка идёт как у обычной папки, без истории), а «Продолжить без истории» (`localrepo.detach_history`, убирает только `.svn`, файлы остаются) — второе действие с подтверждением. Остальные проекты не затрагиваются.
- Папка без истории и без сервера (создана из шаблона без svnadmin, после «Продолжить без истории», обычная папка в «Мои проекты») показана как «Только на этом компьютере»; главная кнопка — «Отправить на сервер…» (без связи кнопка серая, в подсказке сказано почему).
- Если отправка отказала из-за несохранённых правок, окно предлагает «Сохранить их у себя и сразу отправить»: правки сохраняются в историю на компьютере и отправка продолжается одним шагом.

### Отправка на сервер («Отправить на сервер…»)

Кнопка «Отправить на сервер…» в колонке кнопок (для папки без правок) или в «Ещё ▾». В окне — место на сервере (`parent` из шаблона или выбранное), название (имя папки) и комментарий.

- На сервер уходит **только последнее сохранённое состояние** главной линии (`trunk`): без истории, веток и версий. Прежние сохранения остаются на компьютере в архиве.
- Источник: для проекта с историей — экспорт его рабочей копии (`svn export`, то есть то, что лежит в папке); для обычной папки — копия без `.svn`, `.git`, `.hg`, мусора по правилам `filter` и ссылок на другие папки.
- Есть несохранённые правки (в том числе новые файлы в проекте с историей) — отказ «Сначала сохраните их у себя»; окно предлагает «Сохранить у себя».
- Порядок: проверки (сетевой диск, уже на сервере, правки, существование места на сервере, свободное имя) → временная копия `.<имя>.publishN` рядом с папкой → загрузка (`importer.create_project`, с откатом при сбое) → привязка на месте (`.svn` переносится в `.<имя>.svn-old`, `checkout --force`, `project.json` приводится к версии с сервера, файлы с `svn:needs-lock` становятся «только для чтения», `.svn-old` удаляется). Если привязка не вышла, прежний `.svn` возвращается на место.
- Исходная папка до успешной загрузки только читается. Пока идёт отправка, папка помечена занятой (`publish.is_busy`): фоновая проверка и окно её не трогают.
- Если `.svn` держит другая программа (Проводник, TortoiseSVN, антивирус): три попытки переноса с паузой, затем «Закройте окна Проводника и TortoiseSVN с этим проектом и повторите».
- Свойства локальной истории на сервер не переносятся: действуют свойства выбранного места (`svn:auto-props`, `svn:global-ignores` на сервере). `svn:ignore` теряется.
- Место на сервере должно существовать. Программа его не создаёт (в отличие от `svn mkdir --parents`); отказ «Такого места на сервере нет».
- Права: при загрузке отказ AUTHZ объясняется по-русски и проект остаётся на компьютере. Предварительной проверки прав записи нет: отказ приходит при создании папок.
- Если до привязки сбой: проект на сервере остаётся, журнал сохраняется, при повторе «Отправить на сервер…» предлагается «Завершить отправку».

«Сразу на сервер» (окно «Новый проект», пункт «На общем сервере») идёт другим путём: сборка в той же `.<имя>.creating`, загрузка, затем обычное скачивание в итоговую папку под отметкой «занята». Если скачать не вышло, проект на сервере остаётся, в окне есть «Скачать ещё раз». Нет прав на создание — проект остаётся на компьютере (как локальный).

### Содержимое файлов

- Меняются только имена папок и файлов. Текст, docx, xlsx, dwg, skp и любые другие файлы копируются как есть. Подстановка внутрь файлов не делается и в первой версии не планируется.
- Шаблон экспортируется с `--ignore-keywords --ignore-externals`. Побайтовое совпадение с шаблоном гарантируется, если в шаблоне нет свойств `svn:keywords` и `svn:eol-style`. Поведение `svn:eol-style` на живом сервере не проверено (см. `TODO.md`).

### Ограничения

- **Сетевые диски.** Проект нельзя создать, отправить или включить для него историю, если папка лежит на сетевом диске или в сетевом пути (`\\…`). Рабочие копии на сетевых дисках не делаются (`checks.py`, `localrepo`, `publish`).
- **Длина путей:** 200 (предупреждение), 248 для папок и 260 для файлов (отказ). См. «Длина имён и путей».
- **Не сделано в первой версии:** подстановка внутрь файлов; перенос истории на сервер; ветки и версии локальной истории; редактор шаблонов; ограничение `project_creators`; обновление уже созданных проектов при изменении шаблона; выпадающие списки и проверка по маске у полей; чтение `links` из `project.json`.
- **Не проверено на живом сервере:** права authz при создании, отсутствие места на сервере, `svn:eol-style` в шаблоне, обрыв VPN посреди загрузки. Список — в `TODO.md`.

## Доступ для ИИ-агентов

ИИ-помощник (Claude Code, Claude Desktop или другой клиент MCP) может смотреть проекты конструктора: что изменилось, что нового у коллег, историю, занятые файлы. Пароль ему не передаётся: вход берётся из кэша svn, который заполняет окно при входе. Читать он может всегда. **Запись (получить новое, сохранить на сервер или у себя, занять и освободить файл, ветки и версии, отмена своего сохранения, создать проект, отправить на сервер) есть, но по умолчанию выключена** и включается отдельно, по частям (см. «Запись: два шага, три режима»). На живом сервере запись не проверялась.

Документы: план и решения `docs/PLAN_agent_access.md`, записи для разработчиков `docs/DECISIONS.md` (запись от 2026-11-03), подключение для администратора `docs/agent/INSTALL_AGENT.md`, открытое и ручные проверки `TODO.md`.

### Два exe

| Файл | Что это | Сборка |
|------|---------|--------|
| `SVN-lite.exe` | окно программы без консоли: трей, уведомления, самообновление | `packaging\SVN-lite.spec`, точка входа `svn_helper.py` |
| `svnlite.exe` | консольная программа: команды чтения (`svnlite projects --json` и др.) и подкоманда `svnlite mcp`, сервер для Claude | `packaging\svnlite.spec`, точка входа `svnlite_cli.py`; `console=True`, без tkinter |

Оба лежат в одной папке. `packaging\release.py` собирает обе версии, но в папку обновлений кладёт только окно: `svnlite.exe` попадает туда лишь с флагом `--with-cli`, потому что консольную программу нельзя раздавать на все ПК, пока ИТ не согласовали её и антивирус не проверил. Раздача `svnlite.exe`: вручную администратором или выпуском `release.py --with-cli`. Самообновление окна обновляет `svnlite.exe` только там, где он уже лежит рядом с окном, и сам его не ставит. Окно и `svnlite.exe` не мешают друг другу: консольная программа не открывает окно, не берёт его мьютекс и не трогает трей и `svn_helper.log`. Сервер MCP закреплён на `mcp==1.30.0` (`requirements-mcp.txt`, обоснование в `docs/DECISIONS.md`).

### Как подключить

Полная инструкция с ручными проверками: `docs/agent/INSTALL_AGENT.md`. Кратко:

1. Положить `svnlite.exe` рядом с `SVN-lite.exe` (например, `C:\Program Files\SVN-lite\`). Python на ПК не нужен. Нужен `svn.exe` из TortoiseSVN с «command line client tools»: без него команды отвечают кодом 9.
2. Сотрудник один раз открывает SVN-lite и входит на сервер. Для помощника нужен сохранённый вход: при входе с выключенным «Запомнить пароль» окно не пишет кэш svn (`--no-auth-cache`), и команды отвечают кодом 4 («нужен вход»). Флажок по умолчанию включён.
3. **Claude Desktop:** блок `mcpServers` из `docs/agent/claude_desktop_config.sample.json` добавить в `%APPDATA%\Claude\claude_desktop_config.json` (путь в примере заглушка), перезапустить Claude Desktop. В нём нет Bash, поэтому правила поведения `docs/agent/AGENT_RULES.md` вставляются в инструкции проекта.
4. **Claude Code, подключение:** `claude mcp add --scope user svnlite -- "C:\Program Files\SVN-lite\svnlite.exe" mcp` (или файл `.mcp.json` по образцу `docs/agent/mcp.json.sample`, но не внутри папок проектов). Перезапустить Claude Code.
5. **Claude Code, правила:** папка `%USERPROFILE%\.claude\skills\svn-lite\` с `docs/agent/SKILL.md` и рядом `AGENT_RULES.md`; блок `permissions` из `docs/agent/claude_code_permissions.sample.json` в `%USERPROFILE%\.claude\settings.json` (списки объединить, ничего не затирая). Skill вызывает `svnlite` по имени, поэтому папка с `svnlite.exe` должна быть в PATH.
6. Команду для шага 4 и настройку для шага 3 можно скопировать в окне: «Справка → ИИ-помощник…». Команда берёт путь к `svnlite.exe`, лежащему рядом с программой.

Файлы помощника не класть в папки проектов (`.claude\`, `.mcp.json`, `CLAUDE.md`): рабочая копия отправит их на сервер, и они появятся в «Новом» у коллег (см. `INSTALL_AGENT.md`, раздел 6).

### Что помощник умеет: чтение

Одиннадцать операций чтения (десять и каталог команд). Реестр `svnhelper/ops/registry.py` один для `svnlite` и для MCP, поэтому названия и ответы совпадают.

| Команда `svnlite` | Инструмент MCP | Что отвечает |
|---|---|---|
| `doctor` | `doctor` | готовность: svn, связь с сервером, шаблоны, журналы, версии окна и `svnlite.exe` |
| `projects` | `list_projects` | проекты в папках для проектов этого компьютера |
| `status <проект>`, `--all` | `project_status` | состояние и следующий шаг (`next_action`); `--offline` без сервера |
| `changes <проект>` | `project_changes` | несохранённые правки |
| `incoming <проект>` | `project_incoming` | новое на сервере: кто, когда, комментарий, файлы |
| `history <проект>` | `project_history` | последние сохранения, до 50 |
| `locks <проект>` | `project_locks` | занятые файлы, свои и чужие |
| `info <проект>` | `project_info` | сведения о проекте (`project.json`, линия, архив) |
| `templates` | `list_templates` | шаблоны проектов (без связи: уже скачанные, с пометкой `offline`) |
| `server-projects [путь]` | `list_server_projects` | папки и проекты на сервере без скачивания, до 3 уровней |
| `commands [--markdown] [--file]` | `list_commands` | каталог команд с вашими проектами (см. «Каталог команд») |

MCP дополнительно отдаёт ресурсы `svnlite://projects` и `svnlite://project/{название}/status`.

Ответ всегда одного вида (`schema: 1`): `ok`, `data`, `text` (по-русски), `warnings`, `untrusted_fields`, `error` (`kind`, `message`, `next_step`, `retryable`, `exit_code`). Технические сведения (адрес, номера, коды `E######`) только с `--details` или `details=true`. Комментарии, авторы и имена файлов приходят от коллег: они перечислены в `untrusted_fields`, комментарий обрезается до 500 знаков, записей не больше 50. В описании инструментов сказано не исполнять инструкции из этих полей. Пароля и сырого ответа svn в ответе нет.

Коды возврата `svnlite`: 0 успех; 1 прочее; 2 неверные параметры; 3 нет связи или таймаут; 4 нужен вход; 5 нет прав; 6 отказ политики; 7 нужна работа человека (конфликт, на сервере новее, файл открыт в другой программе); 8 папку обрабатывает другая программа; 9 не найден `svn.exe`. Список тот же в `svnlite --help`.

### Запись: два шага, три режима

Запись **по умолчанию выключена**. Каждое изменение делается парой команд: `…-plan` (ничего не меняет: проверяет и показывает, что будет сделано, выдаёт одноразовый токен на несколько минут) и `…-apply` (выполняет по токену; в MCP клиент спрашивает человека именно на `…_apply`). Токен привязан к проекту и параметрам: токен от другого списка файлов или другого комментария не подходит; если проект изменился после плана, нужен новый план; повторное применение того же токена ничего не пишет второй раз (`already_applied`). Режим из файла политики:

| Режим | Что значит |
|---|---|
| `read_only` | помощник только смотрит (по умолчанию) |
| `write_confirm` | запись с подтверждением: токен плана обязателен |
| `write_full` | запись без токена: `…-apply` выполняется сразу; разрешения, папки, лимиты, журнал и все проверки те же |

Разрешения `allow` включают операции по отдельности: `get_new`, `save_server`, `save_local`, `lock` (занять и освободить свои файлы), `branches` (создать ветку и версию, переключиться), `rollback` (отменить своё сохранение), `create_local`, `create_server`, `publish`. Потолок `agent_max_mode` сильнее; при потолке `write_confirm` режим `write_full` работает как `write_confirm` (токен плана нужен всегда, это видно в `doctor`). Лимиты: файлов и удалений в одном сохранении, записей в час (общий счётчик всех процессов), наименьшая длина комментария; к комментарию добавляется «(по просьбе ИИ-помощника)».

| Операция | План и применение (`svnlite`) | Инструменты MCP | Отказы |
|---|---|---|---|
| Получить новое | `get-new-plan`, `get-new-apply` | `get_new_plan`, `get_new_apply` | конфликт: код 7, ответ с перечнем файлов; починка папки не вызывается |
| Сохранить на сервер или у себя | `save-plan`, `save-apply` (`--message-file`, `--files`, `--allow-deletes`, `--local`) | `save_plan`, `save_apply` | новое на сервере, конфликт, файл надо занять: 7; версия: 5; лимиты и короткий комментарий: 6 |
| Занять и освободить файлы | `lock-plan/apply`, `unlock-plan/apply` | `lock_*`, `unlock_*` | чужой занятый файл: 5, не ломается |
| Ветка, версия, переключение | `branch-plan/apply`, `switch-plan/apply` | `branch_*`, `switch_*` | имя занято: 1; переключение с правками или занятыми файлами: 7 |
| Отмена своего сохранения (проект с сервера или с историей на компьютере) | `rollback-plan`, `rollback-apply --revision N` | `rollback_*` | чужое сохранение: 6; после него файлы менял другой: 7; отмена отмены возвращает вперёд |
| Создать проект из шаблона, отправить папку | `create-project-plan/apply`, `publish-plan/apply` | `create_project_*`, `publish_*` | `create_server`, `publish` включаются отдельно |

Комментарий к сохранению, ветке или отмене передаётся только файлом UTF-8 или со стандартного ввода (`--message-file`), а не строкой командной строки. Отмена сохранения это **новое** сохранение, обращающее правки № N: история не стирается; она возможна, только если сохранение сделано вами, целиком внутри этого проекта и линии, а после него эти файлы никто не менял. Перед записью папку занимает межпроцессный замок (`publish.mark_busy`): занята другой программой (в том числе окном SVN-lite) — код 8, ничего не тронуто. Окно в свою очередь берёт тот же замок на время «Получить новое», сохранения, занятия файлов, переключения и починки папки. Долгая запись в MCP отвечает через 20 секунд `state=running` и `job_id`, ход читает `job_status`. После записи помощник пишет `agent\last_change.json`, окно по нему перечитывает проекты.

### Каталог команд

`svnlite commands` (MCP: `list_commands`) выдаёт каталог всех команд: назначение, параметры, строку для терминала, нужное разрешение и ваши настоящие проекты. Каталог строится из реестра операций и не расходится с программой. Агент использует его, чтобы знать свои возможности. Тем, у кого агента нет: `svnlite commands --file справочник.md` записывает готовый Markdown с вашими проектами и путями; файл можно целиком отдать любому ИИ-чату и попросить подсказать команды для терминала. Пароля в справочнике нет.

### Чего нет и не будет

- **Не будет в помощнике:** разбор конфликта, починка папки, `revert` как команда, удаление на сервере, `--force`, смена пароля, настроек и политики. Команд смены политики в `svnlite` и MCP нет.
- **Переключатели разрешений в окне «Справка → ИИ-помощник…»** (AG.7) делаются отдельным шагом; до него режим и разрешения включает администратор командой `python -m svnhelper.agent_policy set` (`docs/agent/INSTALL_AGENT.md`, раздел 4а).
- Prompts и HTTP-транспорт не делаются. Запись не проверялась на живом сервере `svn://192.168.11.11`.

### Потолок, политика и выключение

- **Потолок** задаёт администратор полем `agent_max_mode` в `svn_helper.json` (см. таблицу настроек). Потолок сильнее выбора сотрудника. Долгоживущий сервер MCP перечитывает потолок и файл политики на каждый вызов, перезапускать клиент не нужно.
- **Политика** (`agent_policy.json` в `%APPDATA%\SvnHelper`): режим, разрешения, дополнительные папки, лимиты записей в час. Режимы `read_only`, `write_confirm`, `write_full`, разрешения `get_new`, `save_server`, `save_local`, `lock`, `branches`, `rollback`, `create_local`, `create_server`, `publish`. Файл подписан через DPAPI; правка руками даёт режим «только чтение». Политику пишет администратор: `python -m svnhelper.agent_policy show` (`set --mode write_confirm --allow get_new,save_server,lock` и `reset` меняют файл); переключатели в окне будут добавлены отдельным шагом. Эта команда запускается только из исходников: на рабочем ПК Python нет, там политику меняет только окно «Справка → ИИ-помощник…». Подпись защищает от случайной правки, но не от враждебной программы того же пользователя.
- **Выключить:** `"agent_max_mode": "off"` в общем `svn_helper.json` (всем) или в файле рядом с программой (одному компьютеру). Тогда все команды, кроме `doctor`, отвечают кодом 6. Аварийно: завершить `svnlite.exe` в диспетчере задач (окно SVN-lite не затрагивается).

### Журнал действий в окне и отмена

«Справка → Журнал действий помощника…» (или кнопка «Открыть журнал действий помощника» в окне «ИИ-помощник…») показывает ленту из файлов `agentudit_ГГГГ-ММ.jsonl`, свежее сверху: когда, кто (консоль `CLI`, `MCP` с именем клиента, `Окно SVN-lite (вы)`), что сделал словами («сохранил изменения», «занял файлы», «создал ветку или версию», «отменил сохранение», «посмотрел: …»), проект, файлы, номер сохранения, итог. Фильтры: «Только изменения» (по умолчанию), «Все действия», «Только чтение»; срок «Этот месяц», «3 месяца» (по умолчанию), «Год» (файлы по месяцам). Под лентой подробности выбранной строки: все записанные файлы и комментарий. Пароля в журнале нет.

Кнопки работают для сохранений (`save_apply`) и для самих отмен:

- **«Отменить это сохранение»**: окно составляет план отмены, показывает, какие файлы изменятся, и спрашивает «Да/Нет». После «Да» в фоне делается **новое** сохранение, обращающее правки сохранения № N (история не стирается). Решение принимает человек: помощник кнопок отмены не получает.
- **«Вернуть отмену»**: то же для строки отмены, возвращает всё вперёд.
- Все проверки делает слой операций (`rollback_*`): сохранение должно быть вашим; после него те же файлы никто не менял; в проекте нет несохранённых правок, нового на сервере и конфликтов. Если файл менял коллега, окно говорит: «После этого сохранения файл менял <кто>. Отменить автоматически нельзя»; ничего не тронуто. Проект с историей только на компьютере, версии (теги), создание проекта и отправка папки не отменяются (в ленте «не отменяется»).
- В ленте видна связь: у отменённого сохранения «отменено сохранением № N», у отмены «отменяет сохранение № N». Для этого в строку журнала добавлено поле `undone_rev` (его пишет `ops/write_undo.py` только после удавшейся отмены; у `rev_after` номер нового сохранения). Старые строки без поля читаются как раньше.
- Окно работает от имени клиента `window` с политикой `agent_journal.WindowPolicy`: разрешена только отмена, потолок администратора и список папок помощника не применяются (это решение человека, а не помощника), лимит записей помощника в час не расходуется, пометки «по просьбе ИИ-помощника» в новом комментарии нет. Папку на время отмены занимает сам слой операций межпроцессным замком (`publish.mark_busy`): ещё один `folderlock.hold` вокруг вызова отказал бы, поэтому окно его не берёт. Отмена идёт со входом на сервер, который уже выполнила программа; пароль в журнал не попадает.

### Журналы и папка данных

| Что | Где | Примечание |
|---|---|---|
| Журнал действий помощника | `%APPDATA%\SvnHelper\agent\audit_ГГГГ-ММ.jsonl` | одна строка JSON на вызов: чтение, отказы и операции (файлы, номера сохранений до и после, номер отменённого сохранения `undone_rev`, комментарий, план и операция); пароля и сырого ответа svn нет; файлы старше 12 месяцев удаляются при первой записи месяца |
| Планы записи | `%APPDATA%\SvnHelper\agent\plans\<токен>.json` | токен, срок, результат; хранятся сутки |
| Журнал работы `svnlite.exe` и MCP | `%APPDATA%\SvnHelper\logs\svnlite_agent_ГГГГ-ММ.log` | по месяцам; файлы старше 3 месяцев удаляются при старте; в stdout не пишет |
| Журнал окна SVN-lite | `%APPDATA%\SvnHelper\svn_helper.log` | отдельный файл, помощник в него не пишет |
| Замки папок | `%APPDATA%\SvnHelper\locks\` | служебные файлы межпроцессного замка; старше 7 дней удаляются |

`svnlite doctor --text` показывает версию, найденный `svn.exe`, откуда взят конфиг, действующий потолок и пути журналов. Переменная `SVNLITE_DATA_DIR` переносит всю папку данных в другое место; она предназначена для тестов и демонстрации. Собранный `svnlite.exe` её игнорирует (`agent_env.harden`): иначе помощник направил бы политику, счётчик записей и журнал в свою папку. Тот же вызов включает строгие замки (нет каталога замков — запись отказывает кодом 8) и привязывает `svn.exe` к процессу (объект «задание» Windows, `jobobject.py`).

## Ручные проверки на Windows (перед выдачей сотрудникам)

1. Первый запуск без `svn_helper.json` рядом: предупреждение, работа по умолчанию. Файл с BOM и кириллицей в `work_dir` читается.
2. Компьютер без TortoiseSVN (или без command line tools): понятная инструкция, кнопки недоступны.
3. Вход с неверным паролем: сообщение «Неверный логин или пароль», до 3 попыток, затем отказ. С верным: второй раз окно входа не появляется.
4. Папка без прав (путь, закрытый в authz): «Нет доступа к этой папке, обратитесь к администратору».
5. Целевая папка непустая; папка с `.svn` внутри (подсказка про SVN Update).
6. Сетевой диск (`\\server\share` и подключённый диск Z:): отказ.
7. Диск, где места меньше 2,2 × размер проекта: отказ с цифрами.
8. Путь длиннее 110 символов: предупреждение, можно продолжить.
9. Отмена скачивания: процесс svn.exe исчезает из диспетчера задач, показано сообщение про частично заполненную папку.
10. Закрытие окна во время скачивания: вопрос, затем остановка svn.exe.
11. Проект с кириллицей и пробелами в пути (`261019_отбраковщик и делитель_тест`), в том числе на «@» и «%» в имени.
12. Отключить сеть/VPN: «Нет связи с сервером, проверьте сеть или VPN».
13. После скачивания файлы Компас/Word/Excel только для чтения; окна «Готово» нет, а в карточке проекта на «Мои проекты» есть напоминание про «Занять файл…» (вкладка «Занятые»).
14. Ссылка: вставить с `/trunk`, без него, с кириллицей и `%20`; кривая ссылка и несуществующий проект дают понятное сообщение. F12 открывает настройки, смена адреса сервера обновляет дерево.
15. Вкладка «Мои проекты»: обычная папка помечена серой, проект с новым сохранением коллеги показывает «Есть новое на сервере», «Получить новое» приносит его; два человека правят один файл: сообщение о конфликте; отмена «Получить новое», затем повторное.
16. Монитор с масштабом 125–150%: текст чёткий, окно не обрезано; кнопки колонки 1 не обрезаются.
17. Сохранение на сервер в программе: правка и новый файл (с кириллицей в имени) сохраняются, список «Изменения» пустеет; «Получить новое» сначала, если на сервере новее; файл с «только для чтения» просит «Занять и сохранить»; сохранение в версию отказано.
18. Крестик окна прячет программу, значок остаётся в трее; значок → «Выйти» при несохранённых правках спрашивает подтверждение.
19. Отключить сеть на минуту: полоса «Нет связи с сервером» появляется один раз; после связи прячется сама.
20. Уведомления: «Проверить уведомления» показывает окошко в правом нижнем углу, не крадёт фокус, закрывается по крестику и по времени; «Позже» откладывает.
21. Автозапуск: включить «Запускать вместе с Windows», перезайти в Windows — программа в трее, окно не открыто; выключить — значение в `HKCU\…\Run` удалено.

## Прототип для показа (2026-10-20)

- **Путь к папке вместо ссылки.** На подвкладке «Скачать проект» в поле ссылки можно вставить `Z:\…` или `\сервер\…`. По настройке `mirrors` программа находит папку в хранилище (после паузы ввода, как список веток): проект есть — подставляется ссылка; подпапка проекта ведёт к самому проекту; проекта нет — «Этого проекта ещё нет на сервере.» и кнопка «Создать проект из этой папки…»; папка вне проектов на сервере — «Эта папка не входит в проекты на сервере.»
- **Создать проект из папки** (окно): исходная папка только читается; сводка «N файлов, объём», предупреждения (.svn/.git, ссылки-junction, открытые документы `~$`, очень большой объём); имя и место в хранилище; комментарий; подтверждение; прогресс и «Остановить». На сервере: `svn mkdir --parents trunk branches tags` (одна ревизия), затем `svn import` в trunk с отсевом мусора (`--config-option config:miscellany:global-ignores=…` из секции `filter`). При сбое или отмене созданное удаляется, если после нашей ревизии в проекте ничего не появилось. После успеха — вопрос «Скачать его к себе, чтобы работать с ним?» и скачивание в папку для проектов на этом ПК (сетевые диски по-прежнему запрещены).
- **«Мои проекты → Ещё ▾»**: добавлено «Отменить мои правки (TortoiseSVN)…» (окно TortoiseSVN Revert).
- Демо: `demo\start_demo.bat` (один щелчок: сервер и программа), `demo\ДЕМО.md` (сценарий показа) и `demo\start_demo_server.ps1` (локальный svnserve на 127.0.0.1:13690).

## Намеренно не сделано в первой версии

- Слияние веток (Merge) в самой программе. Оно выполняется в окне TortoiseSVN, которое программа открывает кнопкой «Перенести правки…». Сохранение на сервер, получение нового, занятие и освобождение файлов, ветки, версии и «Отличия» уже есть в программе.
- Скачивание конкретной ревизии (ветки и версии скачиваются).
- Шифрование соединения (svnserve без TLS: только внутренняя сеть).
- Перезапуск скачивания с места остановки: после отмены папку нужно удалить вручную.
