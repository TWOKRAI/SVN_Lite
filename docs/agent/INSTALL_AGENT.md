# Подключение ИИ-помощника (для администратора)

Помощник это `svnlite.exe`: консольная программа, которая показывает проекты, правки, новое у коллег, историю и занятые файлы, и та же программа с подкомандой `mcp` как сервер для Claude Desktop и Claude Code. Пароль помощнику не отдаётся: он не нужен, а вход делает окно SVN-lite. Сервер: `svn://192.168.11.11`.

**Статус: только чтение.** Запись (сохранять, занимать файлы, создавать проекты, отправлять на сервер) выключена и появится позже отдельной выдачей, после ручных проверок на живом сервере. Этот документ тогда будет дополнен; настройки записи сейчас не нужны. Примеры имён и путей ниже заглушки: подставьте свои.

## 1. Куда положить программу

1. Положите `svnlite.exe` рядом с `SVN-lite.exe` (например, `C:\Program Files\SVN-lite\`). Python на компьютере не нужен.
2. Нужен `svn.exe` из TortoiseSVN с включённой опцией «command line client tools» (тот же, что нужен окну). Без него команды отвечают кодом 9.
3. Для Claude Code добавьте папку с `svnlite.exe` в PATH пользователя: skill и правила разрешений вызывают просто `svnlite`. Проверка в новом окне консоли: `svnlite --version`.
4. Сотрудник один раз открывает SVN-lite и входит на сервер: помощник пользуется сохранённым входом программы, свой пароль не хранит и не спрашивает. Без входа команды отвечают кодом 4.

Окно и трей продолжают работать параллельно: `svnlite.exe` не занимает окно программы.

## 2. Подключить MCP

Примеры конфигурации лежат рядом: `claude_desktop_config.sample.json` и `mcp.json.sample` (в них путь-заглушка к `svnlite.exe`, не копируйте его слепо).

**Claude Desktop.** Добавьте блок `mcpServers` из `claude_desktop_config.sample.json` в `%APPDATA%\Claude\claude_desktop_config.json` (если файл уже есть, вставьте только запись `svnlite` в существующий `mcpServers`). Полностью закройте и снова откройте Claude Desktop. В нём нет Bash, поэтому правила поведения вставьте в инструкции проекта: содержимое `AGENT_RULES.md`.

**Claude Code.** Один из двух способов:

- на пользователя (рекомендуется): `claude mcp add --scope user svnlite -- "C:\Program Files\SVN-lite\svnlite.exe" mcp`;
- файлом `.mcp.json` по образцу `mcp.json.sample`, но **не** внутри папок проектов (см. раздел 6).

Затем перезапустите Claude Code. Инструменты MCP только читающие: `doctor`, `list_projects`, `project_status`, `project_changes`, `project_incoming`, `project_history`, `project_locks`, `list_templates`, `project_info`, `list_server_projects`.

## 3. Подключить skill и разрешения (Claude Code)

1. Создайте папку `%USERPROFILE%\.claude\skills\svn-lite\` и положите в неё `SKILL.md` из этой папки. Название папки и поле `name` в файле: `svn-lite`. Правила поведения лежат в `AGENT_RULES.md`: положите файл рядом (`%USERPROFILE%\.claude\skills\svn-lite\AGENT_RULES.md`), skill на него ссылается.
2. Разрешения: перенесите блок `permissions` из `claude_code_permissions.sample.json` в `%USERPROFILE%\.claude\settings.json` (если там уже есть `permissions`, объедините списки `allow`, `ask`, `deny`, ничего не затирая). Смысл:
   - `allow`: команды чтения выполняются без вопроса;
   - `ask`: всё с `--apply`, а также команды записи (`save`, `lock`, `unlock`, `new-project`, `publish`) требуют подтверждения человека. Этих команд пока нет, правила заготовлены заранее;
   - `deny`: прямые вызовы `svn`, `svn.exe`, `svnadmin` и чтение и правка `%APPDATA%\SvnHelper` и `%APPDATA%\Subversion\auth`.
3. Синтаксис путей и шаблонов сверьте с установленным Claude Code: команда `/permissions` показывает действующие правила, ошибка в файле видна при запуске. В примере пути записаны от домашней папки (`~/AppData/Roaming/...`), потому что переменные среды в правилах не раскрываются.

**Ограничение.** Правила `Read` и `Edit` защищают только файловые инструменты Claude Code. Прочитать файл через `Bash` (например, `type`) они не мешают. Это защита от случайности, а не от враждебной программы того же пользователя; настоящая защита: пароль в профиле Windows и права на сервере.

## 4. Потолок прав и выключение

Администратор задаёт потолок в `svn_helper.json`, поле `agent_max_mode`:

| Значение | Что разрешено |
|---|---|
| `off` | помощник выключен: все операции, кроме `doctor`, отвечают кодом 6 |
| `read_only` | только чтение (по умолчанию, если поля нет) |
| `write` | запись разрешена, если её включил сотрудник в окне (запись пока не выдана) |

Потолок сильнее выбора сотрудника. Файл `svn_helper.json` лежит рядом с программой или общий на сервере (см. README); если заданы оба, действует меньший режим, поэтому одним файлом нельзя поднять потолок другого. Долгоживущий MCP-сервер перечитывает потолок при каждом вызове, перезапускать клиент не нужно.

**Как выключить помощника:**

- сразу всем: `"agent_max_mode": "off"` в общем `svn_helper.json`;
- одному компьютеру: то же в `svn_helper.json` рядом с программой, либо убрать запись `svnlite` из конфигурации клиента, папку `%USERPROFILE%\.claude\skills\svn-lite\` и правила из `settings.json`;
- аварийно: завершить процессы `svnlite.exe` в диспетчере задач (окно SVN-lite это не затрагивает).

## 5. Журналы

| Что | Где |
|---|---|
| Журнал действий помощника (кто, что, когда, какой проект; одна строка JSON на вызов; отказы и чтение тоже пишутся, пароля и сырого ответа сервера в нём нет) | `%APPDATA%\SvnHelper\agent\audit_ГГГГ-ММ.jsonl` |
| Журнал работы программы `svnlite.exe` (технический, для разбора сбоев; файлы старше 3 месяцев удаляются) | `%APPDATA%\SvnHelper\logs\svnlite_agent_ГГГГ-ММ.log` |
| Журнал окна SVN-lite (не смешивается с журналом помощника) | `%APPDATA%\SvnHelper\svn_helper.log` |

Команда `svnlite doctor --text` показывает, где лежат журналы на этом компьютере, версию программы, найденный `svn.exe`, откуда взяты настройки и действующий потолок. Если у сотрудника задана переменная `SVNLITE_DATA_DIR`, все эти папки переезжают в неё; она нужна только для тестов и демонстрации, в работе её быть не должно.

## 6. Почему `.claude/` нельзя класть в рабочие копии проектов

Папка проекта на компьютере это рабочая копия: всё, что в ней появляется, видно как новый файл и попадёт на сервер при сохранении, а затем в раздел «Новое» у коллег. Поэтому внутри папок проектов нельзя создавать `.claude/`, `.mcp.json`, `CLAUDE.md` и заметки помощника.

- Настройки, skill и подключение MCP держите на уровне пользователя: `%USERPROFILE%\.claude\`.
- Claude Code сам создаёт `.claude\settings.local.json` в папке, из которой его запустили, когда человек выбирает «больше не спрашивать». Запускайте его из отдельной рабочей папки вне проектов (например, `Documents\Помощник`), а не из папки проекта.
- Если такой файл всё же оказался в проекте, удалите его до сохранения.

## 7. Ручные проверки перед выдачей

Выполните на ПК без Python, с открытыми окном и треем SVN-lite:

1. `svnlite doctor --text`: svn найден, связь есть, шаблоны настроены (или понятное сообщение), журналы указаны верно.
2. Команды чтения из `cmd`, PowerShell и Git Bash (в Git Bash пути вида `/c/...`): `projects`, `status --all`, `changes`, `incoming`, `history --limit 5`, `locks`, `info`, `templates`, `server-projects`. Кириллица и пробелы в названиях проходят, вывод парсится как JSON.
3. Холодный старт `svnlite.exe`: если дольше 3 секунд, решить про сборку в папку; при вызове из Claude Code не мелькает окно консоли.
4. Нет входа (выйти в окне SVN-lite): ответ с кодом 4 и словами «откройте SVN-lite и войдите»; пароль нигде не запрашивается.
5. Отключить сеть или VPN: код 3 для `incoming`, а `status` отвечает по данным на компьютере.
6. Claude Desktop и Claude Code: спросить «что с моими проектами», «есть ли новое у коллег», «какие файлы заняты». Ответ человеческими словами, без технических терминов и без JSON.
7. Закрыть клиент: в диспетчере задач нет висящих `svnlite.exe mcp` и `svn.exe`.
8. `"agent_max_mode": "off"`: все команды кроме `doctor` дают код 6 и понятный текст; вернуть `read_only`.
9. Запись не доступна: в `svnlite --help` нет команд записи; в журнале `audit_ГГГГ-ММ.jsonl` видны сделанные проверки, пароля нет.
10. Антивирус и защита конечных точек: согласовать с ИТ запуск `svnlite.exe` (консольная программа, запускающая `svn.exe`) и его подпись.
11. Папки проектов не содержат файлов помощника (раздел 6).
