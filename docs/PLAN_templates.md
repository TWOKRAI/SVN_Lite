# SVN-lite: проекты из шаблона

Дата: 2026-10-28 (версия 2, после ревью Opus). Основа: `docs/PLAN_create_project.md` (создание проекта из папки уже есть: `svnhelper/importer.py`, `svnhelper/gui/create_dialog.py`), `docs/PLAN_v3_ui.md` (окно в три колонки), код `svnhelper/` версии 1.2.9.

## Цель

Конструктор создаёт проект по шаблону одной кнопкой: имя главной папки собирается автоматически (`261028_отбраковщик вафель`), файлы шаблона копируются как есть и получают проектные имена, в корне появляется `project.json`. Проект можно положить на общий сервер сразу или позже, а также вести у себя на компьютере (с историей, без связи с офисным сервером).

## Принятые решения

- **Шаблон лежит в SVN**, читается через `svn export`. Копия шаблона кэшируется на ПК: без связи проект создаётся из кэша.
- **Шаблоны находятся автоматически**: в `svn_helper.json` поле `templates_root` (ссылка на папку). Каждая подпапка с `template.json` считается шаблоном. Версия шаблона = ревизия, в которой папка менялась последний раз (её же используем, чтобы не скачивать шаблон заново, если он не менялся). Если `templates_root` пуст или шаблонов нет, окно пишет «Шаблоны не настроены, обратитесь к администратору» (контакт из `support`). Уже созданные проекты при изменении шаблона не трогаются.
- **Содержимое файлов не меняется** (ни текст, ни docx, xlsx, dwg, skp). Подставляются только имена папок и файлов. Шаблон скачивается с `--ignore-keywords --ignore-externals`; побайтовое совпадение гарантировано, если в шаблоне нет `svn:keywords` и `svn:eol-style`.
- **Имя главной папки** задаётся форматом `folder_name` (по умолчанию из `svn_helper.json`, поле `project_folder_format`, у шаблона может быть своё). Дата подставляется автоматически и редактируется в диалоге.
- **Один выбор в диалоге «Где хранить проект»** вместо двух галочек:
  - «На общем сервере: коллеги сразу увидят» (по умолчанию, когда есть связь);
  - «Пока только на этом компьютере: отправлю позже» (по умолчанию без связи, с пояснением «Нет связи с сервером»).
  История у локального проекта включается сама, если найден `svnadmin.exe` (отдельного пункта для неё нет).
- **Место на сервере** берётся из шаблона (поле `parent` в `template.json`, например `konstruktor/projects`) и показывается строкой «Будет на сервере: …» с кнопкой «Изменить…». Имя проекта на сервере = имя главной папки.
- **На сервер уходит только последнее сохранённое состояние главной ветки**, без истории, веток и версий. Перенос истории не делаем.
- **Два пути на сервер, чётко разделённые:**
  - «Сразу на сервер»: проект собирается во временной папке, загружается (`importer.create_project`) и скачивается обычным способом в итоговую папку. `--force` не нужен, атрибуты «только для чтения» ставит сам svn.
  - «Отправить позже»: уже существующая локальная папка привязывается к серверу на месте (`checkout --force`). Только для неё нужны особые меры из T.4.
- **Локальная история** (необязательная): репозиторий на ПК через `svnadmin create` (`svnadmin.exe` лежит рядом с `svn.exe` в TortoiseSVN по умолчанию, подтверждено папкой bin). Вынесена в отдельный этап T.6 после отправки на сервер.
- **Права**: создавать проект может любой, у кого есть запись в выбранной папке (authz). Отдельного списка нет. Предварительной проверки прав записи у `svn://` нет: отказ приходит на создании папок, и это нормально, ошибка объясняется по-русски.
- **Поля**: `date` и `name` есть всегда; шаблон может добавить свои через `fields`. Они доступны как `{{id}}`.

## Форматы

### `template.json` (в корне папки шаблона, в проект не копируется)

```json
{
  "format": 1,
  "title": "Электроника: проект",
  "description": "Папки, спецификация, схемы",
  "folder_name": "{{date}}_{{name}}",
  "parent": "konstruktor/projects",
  "fields": [
    {"id": "date", "label": "Дата", "default": "{{today:yyMMdd}}"},
    {"id": "name", "label": "Название", "required": true, "hint": "например, отбраковщик вафель"}
  ],
  "renames": {
    "README.txt": "README_{{folder}}.txt",
    "docs/Specification/Шаблон каталог спецификация электроника.xlsx": "{{folder}}_спецификация.xlsx"
  }
}
```

- Плейсхолдеры: `{{id}}` любого поля, `{{folder}}` (итоговое имя главной папки), `{{author}}`, `{{today:маска}}`.
- Маски дат: только `yyyy`, `yy`, `MM`, `dd` (не `strftime`); `mm` запрещён (путают с минутами).
- Ключ в `renames`: путь от корня шаблона через `/`. Значение: новое имя файла или папки (только имя, без пути).
- Всё необязательно, кроме `format`; шаблон без `fields`, `renames` и `parent` работает.
- Строгая проверка манифеста, ошибки администратору по-русски: неизвестный `{{x}}`; ключ `renames`, которого нет в шаблоне; два источника в одно имя (сравнение без учёта регистра); `/` или `\` в значении или в подставленном поле; `{{folder}}` внутри `folder_name`; `id` поля совпадает со встроенными (`folder`, `author`, `today`); `parent` не начинается с корня из `repos`.
- Порядок переименований: сначала самые глубокие пути (переименована и папка, и файл в ней).

### `project.json` (в корне главной ветки проекта)

```json
{
  "format": 1,
  "name": "отбраковщик вафель",
  "folder": "261028_отбраковщик вафель",
  "created": "2026-10-28T14:05:00",
  "author": "ivanov",
  "template": {"id": "electronics", "title": "Электроника: проект", "revision": 412},
  "fields": {"date": "261028", "name": "отбраковщик вафель"},
  "svn": null,
  "links": {}
}
```

- `svn`: `null`, пока проект не на сервере; после отправки `{"url": "...", "published": "..."}`. Это справочное поле, решения («Отправить» показывать или нет) принимаются по `svn info` (есть `.svn` и схема `svn://`), а не по файлу: его можно скопировать вместе с чужой папкой.
- Путь к локальному репозиторию в файл не пишется (файл уходит на сервер, а путь `C:\Users\…` там бессмыслен): он хранится в `settings.json`.
- `links`: заготовка под чат и доску задач, клиент не читает.
- Клиент в первой версии берёт из файла название и шаблон для «Мои проекты»; остальное только записывается.

## Общие правила для исполнителей

- Потоки: svn и сеть только в фоне (`self.run_bg`), интерфейс только в главном потоке. Пул потоков для сетевых задач: `app.py` (`_probe_pool`).
- Тексты интерфейса по-русски, без терминов svn (commit, update, revision, lock, checkout, trunk) и без слов «ревизия», «репозиторий», «svnadmin»; `tests/test_ui_texts.py` дополняется этими русскими словами для новых строк.
- Переиспользовать: `importer.create_project` и откат, `server.validate_line_name` (имя на сервере не длиннее 80 символов), `checks.check_target`. Новая функция проверки имён (не очистки): `safe_local_name` молча заменяет символы и не знает `CON`/`NUL`.
- Пути данных брать из `config.data_dir()` (учитывает `SVNLITE_DATA_DIR` демо-режима), а не из жёстко прописанного `%APPDATA%`. Кэш шаблонов, если `data_dir()` в Roaming, класть в `%LOCALAPPDATA%\SvnHelper`.
- Адреса `file:///` строить через `Path.as_uri()` (как в `tests/test_real_svn.py`), не через `server.build_url`.
- Символ `@` в путях: у `export`, `checkout`, `cat`, `status`, `info` разные правила (конечный `@`). Закрывается тестами на каждую команду (T.0).
- Тесты: `python -m unittest discover -s tests`. Существующие тесты проходят.
- Предел итераций: 2 попытки на падающий тест, на третьей `ESCALATION -> teamlead`.
- **Журнал задач.** Операции с побочными эффектами (создание, отправка) пишут журнал `data_dir()/create_jobs/<id>.json` после каждого шага. При запуске программа разбирает незаконченные задачи: «Завершить отправку» или «Убрать недоделанное».

**Level:** Middle+ (Sonnet) · **Assignee:** developer
**Goal:** недостающие команды в `SvnClient` и исправление ложного «нет связи» для локальных хранилищ.
**Files:** `svnhelper/svn_core.py`, `svnhelper/notifier.py`, `tests/test_core.py`, `tests/fake_svn.py`, `tests/test_real_svn.py`
**Steps:**
1. В `SvnClient` добавить `export` (с `--ignore-keywords --ignore-externals`), `cat`, `checkout(force=True)` с отдельным разбором строк для уже существующих файлов (прогресс не должен быть нулевым), `propget_needs_lock`. Расширить `tests/fake_svn.py` (нет `export`, `cat`, `import`, `mkdir`).
2. Таймауты: `_stream` (export, checkout) получает таймаут и отмену; признак «есть связь» = успешный листинг `templates_root` за 10–15 с.
3. Ошибка `E180001` для `file://` (хранилище пропало) = отдельный вид `ErrorKind.LOCAL_HISTORY_MISSING`, а не `NO_CONNECTION`. Проект на `file://` не влияет на индикатор связи и не прерывает `check_projects` в `notifier.py`.
4. Проверка символа `@` на каждой команде.
**Acceptance criteria:**
- [ ] Тест: локальное хранилище переименовали, проверка проектов `svn://` продолжается, полоса «Нет связи» не появляется.
- [ ] Тест `@` и `%` в названии для `export`, `checkout`, `cat`, `status`, `info`.
**Out of scope:** шаблоны, интерфейс.

### Task T.1 — Ядро шаблонов
**Level:** Middle+ (Sonnet) · **Assignee:** developer
**Goal:** найти шаблоны, прочитать манифест, получить копию (с кэшем), построить итоговые имена и проверить название.
**Files:** `svnhelper/templates.py` (новый), `svnhelper/config.py` (`templates_root`, `project_folder_format`), `tests/test_templates.py`
**Steps:**
1. `list_templates(client, root_url)`: `svn list --xml` корня (ревизия последнего изменения берётся оттуда), `svn cat template.json` только у изменившихся подпапок (параллельно); `TemplateInfo(id, title, description, revision, url)`.
2. `load_manifest(...)`: разбор и строгая проверка по правилам выше, понятные ошибки.
3. `fetch_template(client, info, cache_dir, cancel)`: кэш показывается сразу, обновление идёт в фоне; при успехе копия кладётся в кэш с `meta.json` (ревизия, дата). Заранее (при запуске, если есть связь) кэш прогревается. Без кэша и без связи: «Нет связи с сервером, а этот шаблон на компьютер ещё не скачивался. Подключитесь к сети или VPN и откройте окно снова».
4. `build_plan(manifest, values) -> Plan(folder, renames, warnings, errors)`: подстановка, проверка имён (запрещённые символы, зарезервированные имена Windows, точка и пробел в конце, пустое имя, имя на сервере через `validate_line_name`), длина самого длинного итогового пути: предупреждение по `filter.path_warn_length` из конфига (по умолчанию 200), отказ при 260.
5. `apply_plan(plan, template_dir, target_dir)`: копирует шаблон (пустые папки сохраняются), переименовывает, `template.json` не копируется.
**Acceptance criteria:**
- [ ] Шаблон из примера (`Шаблон проекта`: 8 пустых папок, `docx`, `xlsx`) копируется 1:1, пустые папки на месте, содержимое файлов побайтово совпадает.
- [ ] Тесты: кириллица, пробелы, `@`, `%`; запрещённые символы; `CON`/`NUL`; дубль папки; длина пути; битый манифест; все правила проверки `renames`; регистр и вложенные переименования; кэш без связи; без кэша и без связи; шаблон с `svn:keywords`.
**Out of scope:** `project.json`, привязка к SVN, интерфейс.

### Task T.4 — Отправка на сервер («Отправить позже»)
**Level:** Senior (Opus) · **Assignee:** teamlead
**Goal:** отправить последнее состояние локальной папки на сервер и привязать папку на месте.
**Files:** `svnhelper/publish.py` (новый), `svnhelper/importer.py` (только вызовы), `tests/test_publish.py`
**Steps:**
1. Проверки до начала: папка не на сетевом диске (отказ по типу диска, как в `checks.py`); нет `.svn` с `svn://` (иначе проект уже на сервере); для проекта с `file://` нет несохранённых изменений и нет новых несохранённых файлов (иначе GUI предлагает «Сохранить у себя»); `url_exists(parent)`: места нет — отказ «Такого места на сервере нет» (`mkdir --parents` иначе создал бы новые папки); имя свободно (`url_exists`).
2. Папка помечается занятой (`_path_busy`, пропуск в `notify_ui.py`), чтобы фоновая проверка и TortoiseSVN не держали её.
3. Источник: для `file://` `svn export file:///…/trunk` во временную папку; для обычной папки копия без `.svn`, `.git`, мусора.
4. В экспорте обновляется `project.json` (`svn.url`, `published`), затем `importer.create_project` (три папки, загрузка, откат при сбое). Журнал задачи после каждого шага.
5. Привязка на месте:
   - если есть `.svn`, переименовать в скрытую соседнюю папку на том же диске (`<база>\.<имя>.svn-old`); при ошибке доступа (WinError 5/32) повторить 3 раза, затем «Закройте окна Проводника и TortoiseSVN с этим проектом и повторите»;
   - `svn checkout <URL>/trunk --force` в папку проекта;
   - для файлов с `svn:needs-lock` (`svn propget -R`) выставить атрибут «только для чтения» вручную (после `--force` svn его не ставит);
   - `svn revert project.json`, `svn status` чистый; `.svn-old` удалить;
   - если привязка не удалась, `.svn` вернуть на место.
6. Сбой после загрузки и до привязки: проект на сервере остаётся, журнал сохраняется; при повторе «Отправить» и ошибке `EXISTS` с журналом предлагается «Завершить отправку».
7. «Сразу на сервер» (из T.5) идёт другим путём: сборка во временной папке, `create_project`, обычное скачивание; шаги 2, 5 сюда не относятся.
**Acceptance criteria:**
- [ ] Тест на настоящем svn: папка → сервер → привязана, `status` чистый, файлы с `svn:needs-lock` только для чтения, `project.json` совпадает с серверным.
- [ ] Тест: `.svn` держит другой процесс (открытый `wc.db`): три повтора и понятная ошибка, папка не испорчена.
- [ ] Тест: сбой загрузки откатывает сервер; отмена; убили процесс; проект уже существует; нет прав; место на сервере не существует; сетевой диск.
- [ ] Исходная папка не меняется до успешной загрузки (сравнение хэшей).
**Out of scope:** перенос истории, ветки и версии, окно.

### Task T.5 — Окно «Новый проект»: сервер
**Level:** Middle+ (Sonnet) · **Assignee:** developer
**Goal:** «На общем сервере» и кнопка «Отправить на сервер…» в окне.
**Files:** `svnhelper/gui/new_project_dialog.py`, `svnhelper/gui/projects_tab.py`, `svnhelper/gui/download_tab.py` (выбор места), `tests/test_gui_smoke.py`
**Steps:**
1. Пункт «На общем сервере»: строка «Будет на сервере: …» (из `parent` шаблона) и «Изменить…» (выбор места на сервере; дерево сейчас зашито в `download_tab.py`, вынести в переиспользуемый виджет). В предпросмотре проверка `url_exists` для имени проекта.
2. Сборка, загрузка, обычное скачивание в итоговую папку. Прогресс и «Остановить», откат при сбое.
3. «Ещё → Отправить на сервер…» для локальной папки без привязки: проверка T.4, диалог места и комментария, текст «На сервер уйдёт последний сохранённый вариант. Прежние сохранения останутся только на этом компьютере».
4. Нет прав: «Нет прав создавать проекты в этой папке сервера. Проект создан на компьютере: отправить можно позже или попросить администратора».
**Acceptance criteria:**
- [ ] Smoke-тест: оба пути (сразу и позже) на фейке; отказ без прав оставляет локальный проект.
- [ ] Без связи пункт «На общем сервере» недоступен с подсказкой, по умолчанию выбран локальный.
**Out of scope:** локальная история.

### Task T.6 — Локальная история
**Level:** Middle+ (Sonnet) · **Assignee:** developer
**Goal:** вести историю проекта на своём компьютере без сервера и сохранить совместимость с «Мои проекты».
**Files:** `svnhelper/localrepo.py` (новый), `svnhelper/config.py` (`find_svnadmin`), `svnhelper/gui/projects_tab.py`, `svnhelper/gui/project_panel.py`, `tests/test_localrepo.py`, `tests/test_gui_smoke.py`
**Steps:**
1. `find_svnadmin()`: рядом с найденным `svn.exe`; нет — `None` (локальный проект создаётся без истории).
2. `create_local_repo(folder, ...)`: репозиторий в `<папка проектов>\.svnlite\history\<короткий id>` (тот же диск, скрытый, README внутри, сетевой диск запрещён), `svn mkdir` `trunk`, `branches`, `tags` через `file:///`, `svn import` в `trunk`, `svn checkout --force` в ту же папку. Путь к хранилищу записывается в `settings.json`.
3. Сбой посередине: созданный репозиторий и `.svn` удаляются, папка проекта остаётся нетронутой (журнал).
4. «Мои проекты» для проекта на `file://`: главная кнопка «Сохранить у себя» (вместо «Сохранить на сервер»), нет «Занять файл…» и «Ветки», вместо адреса «Хранится только на этом компьютере», главная кнопка при чистой папке «Отправить на сервер…». При отказе отправки из-за несохранённых изменений (`LOCAL_CHANGES`) окно предлагает кнопку «Сохранить у себя».
5. Пропавшее хранилище (папку скопировали на другой ПК или удалили): состояние «История на этом компьютере потеряна», кнопка «Продолжить без истории» (убирает `.svn`), остальные проекты не страдают (T.0).
6. После отправки на сервер локальное хранилище остаётся как архив (удаляется только по явной кнопке).
**Acceptance criteria:**
- [ ] Тест на настоящем svn: создание, правка, сохранение, ревизия выросла, `status` чистый, кириллица и пробелы в путях.
- [ ] Откат при сбое возвращает папку к исходному виду.
- [ ] Smoke: проект на `file://` показывает упрощённую карточку; без `svnadmin.exe` история не создаётся, ошибки нет.
**Out of scope:** ветки и версии локально, перенос истории.
