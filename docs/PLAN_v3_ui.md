# SVN-lite v3: рабочее окно в три колонки и сохранение на сервер в программе

Дата: 2026-10-26. Основа: прототип в три колонки, согласованный с владельцем, `PLAN_v2.md` (раздел 4 «Упрощения UX»), код `svnhelper/` версии 1.2.9.

## Цель

Обычный сотрудник работает в одном окне и не открывает TortoiseSVN:
- видит свои проекты и их состояние;
- сохраняет правки на сервер (commit) и получает новое (update) прямо в программе;
- смотрит ветки и версии выбранного проекта, а не отдельной папки.

## Целевой вид

```
┌ шапка: SVN-lite · логин · «На связи / Нет связи» ───────────────────────────────┐
│ [полоса «Нет связи с сервером (VPN?)…» — только когда связи нет]                  │
├──────────────┬────────────────────┬───────────────────────────────────────────────┤
│ 1. Кнопки    │ 2. Проекты    [‹]  │
│              │ Папка:[C:\proj ▾][…]│ 3. Состояние проекта                     [›]  │
│ (имя проекта)│ [Найти проект    ] │ Название · ● статус · Ветка: Основная         │
│ Получить новое│ ● 20261022 сушилки│ [Изменения 3][Новое][История][Занятые][Ветки]  │
│ Сохранить…   │ ● 261019_отбрак…   │  ☑ файл.cdw  изменён 🔒                        │
│ Занять файл… │                    │  Что вы сделали? [________] [шаблоны]          │
│ Освободить…  │                    │  [Сохранить отмеченное]                        │
│ Ветки и версии│                   │                                               │
│ Открыть папку│                    │                                               │
│ Откр. на серв.│                   │                                               │
│ Ещё ▾        │                    │                                               │
│ Скачать проект│                   │                                               │
└──────────────┴────────────────────┴───────────────────────────────────────────────┘
```

Правила колонок:
- Колонка 1 (кнопки) не сворачивается. Кнопка главного действия (по состоянию проекта) в стиле `Accent.TButton`, остальные обычные.
- Колонка 2 сворачивается в узкую полосу «Проекты». Колонка 3 сворачивается в полосу «Состояние».
- Колонка 3 свёрнута → колонка 2 занимает её место и показывает таблицу: Проект, Состояние, Ветка, Изменён.
- Кнопка слева, ведущая во вкладку колонки 3 («Сохранить на сервер», «Занять/Освободить», «Ветки и версии»), разворачивает колонку 3 на нужной вкладке.
- Состояние свёрнутости запоминается в `settings` (как `mine_sort`).
- Вкладки окна: «Мои проекты» (первая, открывается при запуске) и «Скачать проект». Вкладка «Ветки и версии» исчезает, её содержимое уходит во вкладку «Ветки» колонки 3.

## Принятые решения

- **Сохранение на сервер делает программа** (`svn add` / `svn rm` / `svn commit`). Это основной путь. Commit через окно TortoiseSVN остаётся дополнительным путём: «Ещё → Сохранить через TortoiseSVN…» (нынешний `_on_tortoise("commit")` с повторной проверкой после закрытия окна). Без TortoiseSVN пункт скрыт, основной путь работает.
- **Папок для проектов может быть несколько.** Выбор папки остаётся над списком проектов (колонка 2): выпадающий список сохранённых папок, «Выбрать…» и «Найти проекты». Смена папки сразу пересобирает список проектов. Список папок хранится в `settings` (`project_dirs`), последняя выбранная — текущая. На вкладке «Скачать проект» папка выбирается из того же списка.
- **Работа в основной ветке.** «Отправить на утверждение» из PLAN_v2 вне этого плана, добавится позже как ещё одно состояние главной кнопки.
- **Слово «Обновить» не используется для разных вещей.** Проверка состояния — иконка «⟳» с подсказкой «Проверить состояние», получение с сервера — «Получить новое».

## Общие правила для исполнителей

- Потоки: svn и сеть только в фоне (`self.run_bg`), интерфейс только в главном потоке (см. `svnhelper/gui/__init__.py`).
- Тексты интерфейса по-русски, без терминов svn (commit, update, revision) в основном тексте.
- Тесты: `python -m unittest discover -s tests`. Все существующие тесты должны проходить; тесты, которые проверяют удалённое поведение, переписываются, а не удаляются молча (в отчёте список).
- Новые функции ядра покрываются тестами в `tests/test_core.py` (фейк `tests/fake_svn.py`) и, где нужен настоящий svn, в `tests/test_real_svn.py`.
- Предел итераций: 2 попытки на падающий тест, на третьей `ESCALATION -> teamlead`.

### Task A.2 — Ядро: сохранение на сервер и сведения о новом
**Level:** Middle+ (Sonnet)
**Assignee:** developer
**Goal:** дать GUI функции для commit, списка своих правок и списка нового на сервере.
**Files:** `svnhelper/svn_core.py`, `tests/test_core.py`, `tests/fake_svn.py`, `tests/test_real_svn.py`
**Steps:**
1. `WcStatus`: добавить `local_changes: list[LocalChange]` (путь, вид: `modified|added|deleted|missing|unversioned|conflicted`, `locked_by_me: bool`, `needs_lock: bool`) и `incoming_files: list[str]` (из `status -u`, `wc-status` с `repos-status`). Существующие поля и счётчики не менять.
2. `SvnClient.commit(path, files, message, cancel) -> CommitResult(revision, committed: list[str])`:
   - `unversioned` из `files` → `svn add --parents`; `missing` → `svn rm --keep-local`;
   - `svn commit --message-file <tmp utf-8> --targets <tmp>` (кириллица в путях и комментарии, длинные списки);
   - разбор «Committed revision N.» и ошибок: `OUT_OF_DATE` (уже есть), новый `ErrorKind.LOCK_REQUIRED` (файл с `svn:needs-lock` не занят), `ErrorKind.READ_ONLY_LINE` для тега (если сервер вернул ошибку хука).
3. `SvnClient.incoming_log(path, cancel) -> list[LogEntry]` — `svn log -r BASE+1:HEAD -v --xml` по корню копии: кто, когда, комментарий, файлы.
4. `SvnClient.diff_summary(url_a, url_b, cancel) -> list[tuple[str, str]]` — `svn diff --summarize --xml` (путь, вид изменения).
5. Мусор среди `unversioned` отмечается через `audit.junk_among` и в `local_changes` не попадает.
**Acceptance criteria:**
- [ ] Тест на настоящем svnserve: изменить, добавить, удалить файл с кириллицей → `commit` → версия выросла, `status` чистый.
- [ ] Тест: commit при новом на сервере даёт `ErrorKind.OUT_OF_DATE`.
- [ ] Тест: файл с `svn:needs-lock` без блокировки даёт `LOCK_REQUIRED`.
- [ ] Тесты на разбор XML `incoming_log` и `diff_summary` на фейке.
**Out of scope:** любой GUI.

### Task B.2 — Поток сохранения на сервер
**Level:** Middle+ (Sonnet)
**Assignee:** developer
**Goal:** кнопка «Сохранить на сервер» сохраняет правки без TortoiseSVN и объясняет каждую проблему одним следующим шагом.
**Files:** `svnhelper/gui/projects_tab.py`, `svnhelper/messages.py`, `svnhelper/gui/app.py`, `tests/test_gui_smoke.py`
**Steps:**
1. `_on_commit` больше не открывает TortoiseSVN, а показывает `CommitPanel` для выбранного проекта (до этапа C — в модальном окне `Toplevel`; в C.3 панель переедет в колонку 3).
2. Перед commit: проект на версии (теге) → отказ «Версию менять нельзя, создайте ветку»; занята другая задача папки (`_path_busy`) → отказ.
3. `OUT_OF_DATE` → вопрос «На сервере есть новее. Получить новое и затем сохранить?» → update, затем повтор commit тем же списком и комментарием. Конфликт после update → остановка и кнопка «Разобрать конфликт».
4. `LOCK_REQUIRED` → «Файл X нужно сначала занять» с кнопкой «Занять и сохранить».
5. Успех: сообщение «Сохранено на сервер: N файлов» в подсказке и в карточке; повторная проверка статуса; если остались занятые мной неизменённые файлы — предложить освободить (пункт TODO).
6. Закрытие программы при несохранённых правках в любом проекте: вопрос «Есть несохранённые правки в …. Закрыть?».
7. Комментарий добавляется в последние комментарии (`settings`).
**Acceptance criteria:**
- [ ] Тест на фейке: успешный commit, повтор после OUT_OF_DATE, LOCK_REQUIRED, тег.
- [ ] Без TortoiseSVN кнопка «Сохранить на сервер» доступна (удалить подпись «Установите TortoiseSVN…»).
- [ ] Commit через TortoiseSVN остаётся пунктом «Ещё → Сохранить через TortoiseSVN…», `test_tortoise_commit_waits_and_rechecks` проверяет этот пункт.

## Этап E — работа в фоне (трей), автозапуск, уведомления (после C)

### Task E.1 — Трей и автозапуск
**Level:** Middle+ (Sonnet) · **Assignee:** developer
**Goal:** программа живёт в трее Windows и по желанию стартует вместе с системой.
**Files:** `svnhelper/tray.py` (новый), `svnhelper/autostart.py` (новый), `svnhelper/gui/app.py`, `svnhelper/gui/settings_dialog.py` (или существующее окно настроек), `svnhelper/config.py`, `tests/`
**Steps:**
1. Значок в трее (меню: «Открыть», «Проверить сейчас», «Выйти»); закрытие окна крестиком сворачивает в трей (настройка «Сворачивать в трей при закрытии», по умолчанию вкл), «Выйти» закрывает совсем, с проверкой несохранённых правок из B.2.
2. Автозапуск через `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, переключатель в настройках «Запускать вместе с Windows» (по умолчанию выкл); запуск из автозапуска — сразу свёрнутым в трей (ключ `--tray`).
3. Библиотека трея (pystray или аналог) — выбрать минимальную по зависимостям; потоки: события трея передаются в главный поток tkinter через очередь/`after`.
**Acceptance criteria:**
- [ ] Включение/выключение автозапуска пишет и удаляет значение реестра (тест с подменой реестра).
- [ ] Закрытие крестиком не завершает процесс; «Выйти» завершает.

### Task E.2 — Фоновая проверка и уведомления
**Level:** Middle+ (Sonnet) · **Assignee:** developer
**Goal:** уведомления о новом по проектам, обновлениях программы и напоминание сохранить правки.
**Files:** `svnhelper/notifier.py` (новый), `svnhelper/gui/app.py`, окно настроек, `svnhelper/config.py`, `tests/`
**Steps:**
1. Периодическая проверка в фоне (интервал в настройках, по умолчанию 15 мин, только если есть связь): для каждого проекта `status -u` → «В проекте X есть новое от Иван (N файлов)». Одно уведомление на проект, пока не изменилось число новых.
2. Обновления самой программы/системы: использовать существующий механизм проверки версии (если есть), иначе заглушка с интерфейсом `check_app_update()`; уведомление «Доступна новая версия SVN-lite».
3. Напоминание о сохранении: есть несохранённые правки дольше N часов (по умолчанию 4) → «В проекте X есть несохранённые правки — сохраните на сервер»; повтор не чаще раза в N часов; не напоминать о проектах с конфликтом/версией-тегом.
4. Показ: собственное всплывающее окно в **нижнем правом углу** экрана (безрамочный `Toplevel`, поверх остальных окон, над панелью задач с учётом рабочей области и масштаба 125–150%, без кражи фокуса), а не системный toast Windows (у нас окошко в том же углу, но своё). Несколько уведомлений складываются стопкой, автоскрытие через ~15 с, кнопки «Открыть» и «Позже», крестик. Значок в трее с точкой, пока есть непрочитанные. Клик «Открыть» показывает программу на нужном проекте и вкладке (`open_project_tab`). Напоминание о правках и о новом/обновлениях приходят этим же окном.
5. Настройки (отдельный раздел «Уведомления и фон» в окне настроек, всё хранится в `settings`, значения по умолчанию в `config.py`, изменения применяются без перезапуска). Подписи простыми словами, у каждого параметра короткая подсказка:
   - «Проверять новое на сервере раз в» — 5 / 15 / 30 / 60 минут / «только вручную» (по умолчанию 15);
   - «Проверять обновления программы» — вкл/выкл и раз в сутки / неделю;
   - «Напоминать сохранить правки, если они не сохранены дольше» — 1 / 2 / 4 / 8 часов / не напоминать (по умолчанию 4);
   - «Напоминать повторно не чаще, чем раз в» — 1 / 2 / 4 часа;
   - «Не беспокоить с … до …» (по умолчанию выкл; например 18:00–09:00 и выходные);
   - «Сколько секунд показывать окошко» — 5 / 15 / 30 / «пока не закрою»;
   - «Показывать только важное»: конфликт и несохранённые правки, без сообщений о новом;
   - по каждому проекту «Не уведомлять об этом проекте»;
   - «Запускать вместе с Windows», «Сворачивать в трей при закрытии» (из E.1);
   - кнопка «Проверить уведомления» — показывает пробное окошко в нижнем правом углу;
   - «Вернуть настройки по умолчанию».
   Некорректные значения (ноль, текст) заменяются на допустимые с понятным сообщением.
**Acceptance criteria:**
- [ ] Тест логики «нужно ли уведомлять» (дедупликация, интервалы, не беспокоить) без GUI.
- [ ] Потоки: проверка в фоне, показ из главного потока.
**Out of scope:** уведомления вне Windows, e-mail.

## Параллельность и порядок

| Шаг | Задачи | Можно параллельно |
|---|---|---|
| 1 | A.1, A.2 | да (разные файлы, кроме `messages.py` — A.1 трогает только тексты состояния) |
| 2 | B.1 | параллельно с концом A.2 (интерфейс `LocalChange` зафиксирован выше) |
| 3 | B.2 | после A.2 и B.1 |
| 4 | C.1 | после B.2 |

| 6 | C.5, D.1 | последовательно |
| 7 | D.2, D.3 | в любой момент после C.5 / независимо |
| 8 | E.1, затем E.2 | после C.5 (E.2 использует `open_project_tab` и ядро A.2) |

После этапа C — ревью (`reviewer`): потоки tkinter, отмена задач, тексты без терминов svn.

**Финальное ревью (после этапа E, обязательно, `reviewer` на Opus):**
- Нет костылей: временных обходов, дублирующего кода, мёртвых виджетов и тестов, «заглушек до лучших времён»; каждый обход должен иметь причину в комментарии или быть убран.
- Удобство для человека без знаний Git/SVN: проход по сценариям «получить новое», «сохранить правки», «занять файл», «создать ветку», «нет связи», «конфликт», «закрыл программу с несохранёнными правками». В каждом сценарии: не больше одного очевидного следующего шага, понятные русские слова (никаких commit, update, revision, lock, checkout, trunk в интерфейсе и уведомлениях: «Сохранить на сервер», «Получить новое», «Занять файл», «Основная ветка»), ошибки объясняют, что делать дальше.
- Проверить все тексты уведомлений и сообщений об ошибках по списку запрещённых слов (автотест на строки интерфейса).
- Замечания ревью исправляет автор кода, затем повторная проверка.
