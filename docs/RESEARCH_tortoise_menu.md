# Исследование: урезанное меню TortoiseSVN в Проводнике (Task D.3)

Статус: только исследование. Код и реестр не менялись, ничего не устанавливалось.
Проверено на машине разработки: TortoiseSVN 1.14.9 (`HKCU\Software\TortoiseSVN\CurrentVersion = 1.14.9.29743`),
Windows 10. Значения масок на этой машине сейчас не заданы (меню по умолчанию).

## 1. Что именно настраивается

Имена значений проверены по строкам в `C:\Program Files\TortoiseSVN\bin\TortoiseSVN.dll` и `TortoiseProc.exe`
(установленная версия 1.14.9), а описание битов взято из официальной документации
([Disabling context menu entries](https://tortoisesvn.net/docs/release/TortoiseSVN_en/tsvn-admins-disablemenus.html)).

Все значения лежат в `HKCU\Software\TortoiseSVN`, тип `REG_DWORD`.

| Значение | Смысл | Подтверждено в 1.14.9 |
|---|---|---|
| `ContextMenuEntriesMaskLow` / `ContextMenuEntriesMaskHigh` | Маска скрытых пунктов: бит = 1 значит пункт СКРЫТ. Low = младшие 32 бита, High = старшие 32. Только Проводник; команды остаются доступны из диалогов TortoiseSVN и командной строки | да, есть в DLL |
| `ContextMenuEntries` / `ContextMenuEntrieshigh` | Какие пункты вынесены на верхний уровень меню, а не в подменю «TortoiseSVN» (то, что в окне настроек TortoiseSVN, страница «Context Menu»). Именно в таком написании: `...high` с маленькой буквы | да, есть в DLL |
| `ContextMenu11Entries` | то же для нового меню Windows 11 | да, есть в DLL |
| `HideMenusForUnversionedItems` | не показывать меню для не версионных путей | да, есть в DLL |
| `NoContextPaths` | список путей, где меню TortoiseSVN не показывается вообще | да, есть в DLL |

Важно: в `PLAN_v3_ui.md` написано `ContextMenuEntries*`. Это неточно: за скрытие отвечают `...MaskLow/High`,
а `ContextMenuEntries/...high` лишь управляют размещением (верхний уровень или подменю).

## 2. Биты, нужные для задачи

Из таблицы документации (64-битная маска: Low = биты 0–31, High = биты 32–63):

- Update = `0x2`
- Commit = `0x4`
- Show Log = `0x20000`
- Остальные известные пункты занимают биты 0–38 и 61–63 (Settings `0x2000000000000000`, Help `0x4000...`, About `0x8000...`).

Чтобы оставить только эти три пункта, скрываем всё остальное, включая неизвестные биты будущих версий:

```
маска_скрытого = NOT (0x2 | 0x4 | 0x20000) = 0xFFFFFFFFFFFDFFF9
ContextMenuEntriesMaskLow  = 0xFFFDFFF9   (4294836217)
ContextMenuEntriesMaskHigh = 0xFFFFFFFF   (4294967295)
```

Чтобы эти три пункта были видны сразу в меню, а не в подменю (иначе «Show log» уйдёт в подменю «TortoiseSVN»):

```
ContextMenuEntries     = 0x00020006   (Update | Commit | Show Log)
ContextMenuEntrieshigh = 0x00000000
```

Оговорка: сами значения и их смысл подтверждены документацией и наличием имён в бинарниках 1.14.9. Фактический вид
меню после записи значений на этой машине НЕ проверялся (запись в реестр вне рамок задачи). Перед внедрением нужна проверка
на тестовой учётной записи. Заодно проверить, как выглядят пункты «SVN Update»/«SVN Commit…» на верхнем уровне и пропадает ли
пустое подменю.

Откат: удалить значения `ContextMenuEntries*`, `ContextMenuEntriesMask*`; меню вернётся к умолчанию.

## 3. Способы применить без правки реестра вручную на машинах

Замечание: любой вариант в итоге приводит к этим же значениям в `HKCU`. «Без правки реестра» здесь значит
«без ручного редактирования и без собственного кода записи в реестр».

| Способ | Как | Плюсы | Минусы |
|---|---|---|---|
| A. Диалог настроек TortoiseSVN, страница «Context Menu» | Пользователь/админ снимает галочки | Официальный интерфейс, ничего писать не надо | Это только размещение (верхний уровень/подменю), а скрыть пункты в GUI нельзя ([документация](https://tortoisesvn.net/docs/release/TortoiseSVN_en/tsvn-admins-disablemenus.html)); вручную на каждой машине |
| B. Групповые политики (GPO) | Настройка пользователя → Preferences → Windows Settings → Registry: 4–6 значений в `HKCU\Software\TortoiseSVN` | Централизованно, применяется при входе, откат снятием политики; штатный механизм домена | Нужен домен/AD и права админа; у TortoiseSVN нет собственных ADMX-шаблонов (политики «в полном смысле» нет, это Preferences); пользователь может изменить значение, оно вернётся при следующем входе |
| C. Параметры установки MSI | У msi TortoiseSVN нет публичных свойств для масок меню (официально документированы только `ADDLOCAL`, `INSTALLDIR`, `REBOOT`, языки и т. п.) | — | Прямого способа нет. Можно только трансформ `.mst` (Orca/InstEd), который добавит записи в таблицу Registry, но в `HKCU` от имени админа они попадают в профиль установщика, не пользователя; трансформ придётся пересобирать при каждом обновлении msi |
| D. Логон-скрипт / запись при старте SvnHelper | `reg add` или `winreg` из `installer.py`/`tortoise.py` в `HKCU` текущего пользователя | Работает без домена, уже есть точка входа (установка msi), применяется ровно к тому пользователю, который работает | Это и есть правка реестра, но автоматическая и обратимая; нужна кнопка/пункт «вернуть меню» и сохранение прежних значений |
| E. Файл `.reg` / импорт | Раздать `.reg` | Просто | Ручной импорт на каждой машине, нет отката и контроля, пользователи путаются |
| F. Профиль по умолчанию (`Default User`, `NTUSER.DAT`) | Загрузить куст и записать значения | Попадёт в новые профили | Не затронет существующих пользователей; хрупко; требует прав админа |
| G. Полностью убрать расширение из Проводника | Политика блокировки shell-расширений (`HKLM\...\Shell Extensions\Blocked`) для CLSID TortoiseSVN | Меню исчезает целиком, один механизм | Пропадают и значки состояния, и все остальные пункты; это HKLM и «ломающая» мера, не наша цель |
| H. Не использовать меню совсем | Вся работа через окно SvnHelper (этапы B–C плана) | Нет зависимости от Проводника, нечего урезать | В Проводнике останутся стандартные пункты TortoiseSVN, пока оно установлено; убрать только удалением TortoiseSVN, чего нельзя, пока нужны его окна (`TortoiseProc`) |

Оговорка по Windows 11: в новом меню (`ContextMenu11Entries`) и в «Показать дополнительные параметры» пункты ведут себя иначе.
На Windows 10 (целевая машина здесь) это не мешает; при переходе на 11 повторить проверку.

## 4. Как применять через `installer.py`

Сейчас `svnhelper/installer.py` ставит msi с `ADDLOCAL=ALL /passive /norestart` под UAC. Рекомендуемая схема (на будущее, в этой
задаче не реализуется):

1. Отдельная функция (например `apply_slim_menu()` в `svnhelper/tortoise.py`), НЕ в повышенном процессе: HKCU должен быть профилем самого сотрудника,
   а msiexec с повышением при другом пользователе пишет не туда.
2. Перед записью сохранить прежние значения в конфиг SvnHelper, чтобы вернуть меню.
3. Включение по настройке (по умолчанию выкл), отдельная кнопка «Вернуть полное меню» (удалить значения).
4. Записать 4 значения из раздела 2 и сообщить об успехе; ошибка записи не должна ломать установку TortoiseSVN.
5. Изменения подхватываются при следующем открытии контекстного меню; перезапуск `explorer.exe` обычно не нужен, но это проверить.

## 5. Рекомендация

1. Основной путь на доменных машинах: GPO Preferences (способ B) с четырьмя–шестью значениями из раздела 2. Централизованно, обратимо,
   без кода в SvnHelper.
2. Если домена нет или нужен самообслуживаемый вариант: способ D, включаемый настройкой в SvnHelper, с сохранением и откатом прежних значений.
3. Способы C, E, F, G не рекомендуются.
4. Решение «руками админа» внедрять только после проверки на тестовой учётной записи (см. раздел 2).

## 6. Риски

- Скрыты не только лишние пункты, но и нужные при нештатной ситуации (Cleanup, Resolve, Revert, Properties, Lock). Для конфликта или
  зависшей блокировки сотрудник не найдёт их в Проводнике; нужно убедиться, что окно SvnHelper покрывает эти случаи, и дать способ вернуть меню.
- «Скрыто» не значит «запрещено»: команды доступны из диалогов TortoiseSVN и командной строки. Это не защита, а упрощение интерфейса.
- Побитовая маска хрупка: новые версии TortoiseSVN могут добавить биты; маска `NOT(...)` скрывает и их, но смысл «остальное скрыто» меняется.
- Обновление TortoiseSVN значения HKCU, как правило, не трогает, но это не гарантировано; нужна проверка после обновления msi.
- Windows 11: другая схема меню и значение `ContextMenu11Entries`.
- Пользователь может сам изменить значения; GPO вернёт их при следующем входе, способ D, только при запуске программы.
- Меню не проверялось в действии на этой машине (по условию задачи реестр не менялся); поведение подменю и верхнего уровня нужно подтвердить на тесте.
