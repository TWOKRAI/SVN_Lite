## 1. Честная оценка

### Что делать
- **Z: как витрина только для чтения**. Это главная идея. Люди продолжают открывать актуальные чертежи там же, где привыкли, а история и откаты уходят в SVN. Без этого пилот не взлетит.
- **Ввод пути с Z: вместо ссылки svn://**. Это дёшево (сопоставление префиксов) и убирает главный барьер: пользователь не знает, что такое URL.
- **Права на «основной» только у утверждающих**. Это штатный authz, кода почти нет.
- **Блокировки (`svn:needs-lock`) на все форматы CAD**. Без них бинарные конфликты будут каждый день.
- **Своя кнопка «Сохранить» в программе**, не в TortoiseSVN. Прошлое решение «Commit только в TortoiseSVN» для этой аудитории неверно: окно TortoiseSVN полно терминов. TortoiseSVN оставить за «Ещё» для опытных.

### Что не делать или резать
- **Слияние бинарных файлов в обычном смысле (svn merge)**. Для Компас/DWG/STEP «слияние» — это всегда замена файла целиком. Значит, «Принять в основной» реализуем как **серверную замену изменённых файлов** одной ревизией (`svnmucc`), а не как `svn merge` в рабочей копии утверждающего. Тогда утверждающему не нужно качать весь проект на 20 ГБ ради принятия трёх чертежей.
- **Своя вкладка «Создать пользователя» с паролями в passwd**. Если в компании есть домен Windows, это выброшенная работа (см. раздел 3).
- **Дерево со столбцами «скачивать / не скачивать / отслеживать»**. В SVN глубина «прилипает» к копии (`--set-depth exclude`), и Update потом не приносит новые файлы. Для пользователя это источник ситуаций «у меня нет файла, а у коллеги есть». Откладываем; остаётся админский фильтр мусора, он уже есть.
- **«Удалить на сервере» из программы**. Риск большой, частота почти нулевая. Админ делает это в TortoiseSVN Repo Browser, а хук защищает от случайностей. Не строим.
- **Вкладка «Ветки и версии» в нынешнем виде**. Для обычного сотрудника её надо убрать с глаз (раздел 4).

### Отложить
«Отвязать», чипы форматов со счётчиком размера, режим «исходная папка = рабочая копия», частичное скачивание, отчёт по всем блокировкам. Всё это делаем после пилота, если о нём попросят.

### Главные риски
| Риск | Тип | Что делаем |
|---|---|---|
| Люди продолжат сохранять на Z: в обход SVN, а `robocopy /MIR` молча сотрёт их файлы | орг + тех | NTFS: Z:\Проекты_SVN доступна на запись **только** служебной учётке публикации. Без этого запускать пилот нельзя |
| Ссылки сборок Компас (.a3d → .m3d) и xref в DWG хранят пути; в копии `C:\Проекты_svn\…` и в папке ветки `…__ветка` они могут сломаться | тех | Проверить на пилотном проекте **до** кода. Если пути абсолютные, нужна единая локальная папка (`C:\Проекты_svn`, одинаковая у всех) и ветка через switch в той же папке, а не отдельная папка |
| Два человека правят один чертёж в разных ветках: блокировка в ветке не мешает правке того же файла в другой ветке | тех | Хук `pre-lock`: занять `branches/*/путь` нельзя, если тот же относительный путь занят в другой ветке или в trunk. Правило «одна задача — свой узел» дополняет хук, но не заменяет его |
| Утверждающий становится узким горлом, правки копятся неделями | орг | Очередь с давностью, напоминание; заместитель утверждающего в authz |
| Несохранённые правки живут только на ПК (локальная копия, бэкапа ПК нет) | тех | В своей ветке «Сохранить» безопасно и не трогает основной вариант: приучаем сохранять ежедневно; напоминание при закрытии программы |
| Нет владельца сервера: хук упал, витрина не обновляется неделю, никто не видит | орг | Назначить сисадмина-владельца; файл «Витрина обновлена: дата, № сохранения» в корне Z:\Проекты_SVN; письмо при ошибке публикации |
| Сервер SVN без бэкапа, «а витрина же есть» | тех | Витрина — не бэкап (только последняя версия). Ночной `svnadmin hotcopy` + копия вне сервера, проверка восстановления раз в месяц |
| svnserve без шифрования, passwd открытым текстом | тех | Только внутренняя сеть; переход на AD (раздел 3) |

### MVP (пилот)
Один проект, 3–5 конструкторов, 1 утверждающий + заместитель, 1 сисадмин.
1. Публикация trunk → Z:\Проекты_SVN (сервер).
2. Главный экран: путь с Z: → «Начать работу» (скачать + создать «мою версию») → «Сохранить» → «Отправить на утверждение».
3. Экран утверждающего: очередь → предпросмотр → «Принять в основной» / «Вернуть на доработку».
4. Блокировки и хуки (trunk защищён, межветочная блокировка, теги только для чтения).
5. Пользователей и права заводит сисадмин вручную (или через AD), вкладки админа в MVP нет.

### Критерий «пилот успешен» (4 недели)
- 0 случаев потери данных и 0 записей мимо SVN на Z:.
- ≥ 15 принятых в основной изменений, медиана «отправил → принято» ≤ 2 рабочих дня.
- Витрина отстаёт от trunk не больше чем на 10 минут в 95% случаев.
- Не больше 1 обращения в неделю на пользователя к сисадмину к концу пилота; ни одного «сломал, не знаю что делать», которое не закрылось кнопкой из программы.
- Конструкторы на опросе не хотят возвращаться на Z: (≥ 3 из 5).

## 2. Архитектура

### Роли
| Роль | Может | authz |
|---|---|---|
| Сотрудник | читать проект, вести свои «мои версии», сохранять в них, отправлять на утверждение | `trunk` = r, `branches` = rw (владение своей веткой проверяет хук) |
| Утверждающий | всё то же + принимать в основной, возвращать, откатывать основной, создавать проект из папки на Z:, фиксировать «выпуск» (тег) | `trunk` = rw, `tags` = rw |
| Админ (сисадмин) | пользователи, группы, права, снятие чужих блокировок, удаление проектов | права на конфиги сервера; в authz в группе `admins` |

### Поток работы
```
Z:\Проекты_SVN\Азов\261019_отбраковщик   (витрина, только чтение)
        │ вставил путь
        ▼
[Начать работу] → checkout trunk в C:\Проекты_svn\… → создаётся ветка branches/ivanov_<задача>, копия переключается в неё
        │ занял чертёж (needs-lock) → правит в Компас → [Сохранить] (commit в свою ветку, сколько угодно раз)
        ▼
[Отправить на утверждение] → свойство svnlite:state=review на папке ветки + комментарий
        ▼
Утверждающий: очередь → предпросмотр (какие файлы, есть ли конфликт с основным) →
[Принять в основной] → svnmucc: заменить файлы в trunk одной ревизией, записать в svnlite:accepted
        ▼
post-commit (trunk) → флаг → воркер публикации → robocopy /MIR → Z:\Проекты_SVN\…
```

**Конфликт при принятии** = файл менялся и в ветке, и в trunk после точки ветвления. Программа не сливает такой файл, а показывает пару «в основном: Петров, 18.10 / в версии: Иванов, 19.10». Утверждающий выбирает один из вариантов или возвращает версию на доработку.

### Словарь интерфейса
| SVN | В интерфейсе |
|---|---|
| repository | сервер проектов |
| trunk | Основной вариант |
| branch | Моя версия / версия «<задача>» (Иванов) |
| tag | Выпуск (снимок, только просмотр) |
| working copy | Папка на моём компьютере |
| checkout | Начать работу / Скачать |
| update | Получить свежее |
| commit (в ветку) | Сохранить на сервер |
| merge в trunk | Принять в основной |
| запрос на слияние | Отправить на утверждение |
| revert | Отменить мои правки (вернуть как было) |
| reverse merge в trunk | Вернуть основной вариант к состоянию от <даты> |
| lock / unlock | Занять / Освободить чертёж |
| conflict | Чертёж изменили двое |
| revision | Сохранение № / дата |
| cleanup | Починить папку |
| switch | Перейти на другую версию |
| out of date | На сервере есть более свежее |

В README и окнах ошибок термины SVN можно давать в скобках только в отчёте для администратора.

### Что где живёт
**Приложение**: сопоставление Z: ↔ URL, главный экран, сохранение, отправка, очередь утверждающего, принятие через `svnmucc`, понятные тексты и откаты.
**Сервер** (`server_hooks/`):
- `pre-commit`: теги только для чтения (есть); запись в `branches/<логин>_*` только автору и утверждающим; удаление папки проекта только `admins`; fail-closed.
- `pre-lock`: межветочная блокировка одного относительного пути.
- `post-commit`: если затронут trunk, только пишет флаг `publish_queue/<проект>` и сразу выходит (коммит не ждёт robocopy).
- Воркер публикации (Планировщик задач Windows или systemd timer, раз в 1–2 минуты, один экземпляр): `svn update` в серверной копии trunk → `robocopy /MIR /XD .svn /R:1 /W:1` → `_ВИТРИНА_ОБНОВЛЕНА.txt`. Открытые файлы пропускаются и докачиваются следующим проходом; ошибка уходит в журнал и письмом.
- `authz` с группами `approvers_<проект>`, `admins`. Права выдаются группам, не людям.

Сопоставление в `svn_helper.json`:
```json
"mirrors": [{"share": "\\\\fs01\\Z\\Проекты_SVN", "url": "svn://192.168.11.11/projects"}]
```
Буква диска приводится к UNC (`WNetGetConnection`), поэтому Z: у разных людей не важен. Путь из старой зоны (`Z:\Specific_projects\…`) получает ответ «Этот проект ещё не на сервере»; кнопка «Перенести на сервер» есть только у утверждающих.

## 3. Админ-вкладка и пользователи

### Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Программа правит `passwd`/`authz` по UNC-шаре | быстро, без новых компонентов | пароли открытым текстом на шаре; гонки двух админов; ошибка в authz закрывает доступ всем |
| B. SSH к серверу | атомарно, права ОС | на Windows-сервере неудобно; ключи раздавать |
| C. Маленький сервис на сервере (HTTP) | валидация в одном месте | новый сервис со своей безопасностью: дороже, чем выгода |
| D. **VisualSVN Server (или Apache + mod_authz_svn) с входом через AD** | пароли доменные: нет создания пользователей и сброса паролей; группы AD = роли; есть GUI и PowerShell; HTTPS | смена `svn://` на `https://`; нужен Windows-сервер; лицензия (проверить текущие условия бесплатной редакции под ваше число пользователей); хуки переносятся |

### Рекомендация: D, если домен есть
Половина задач админ-вкладки — создать пользователя, сбросить пароль, отключить уволенного — в AD уже решена и проверена. Вход по доменному паролю убирает окно логина и хранение паролей в программе. Права выдаются группами AD (`SVN_Azov_Approvers`), и сисадмин ведёт их привычными средствами. Для программы переход дешёвый: `svn.exe` умеет https, `server.build_url` и `parse_project_url` нужно научить схеме `https://`, а хуки и логика веток не меняются. Тогда админ-вкладка в программе сводится к **просмотру** (кто в каких группах, кто что занял) и снятию чужих блокировок. Писать её не обязательно.

Решение принять **до** реализации раздела 5.6, лучше до пилота: пилот на svnserve с последующей миграцией означает двойную работу пользователей (новые адреса, пересвязка копий через `svn relocate`).

### Запасной вариант (домена нет или VisualSVN нельзя): svnserve + authz в репозитории
- `authz-db` в `svnserve.conf` указывает на файл **внутри репозитория** (`svn://…/admin/authz`, поддерживается с svn 1.8). Тогда изменение прав — это обычный коммит: история, автор, откат «Вернуть как было», а проверку `svnauthz validate` делает `pre-commit` (fail-closed: битый authz не сохранится). Доступ к `admin/` только у `admins`.
- `passwd` в репозиторий положить нельзя. Его правит программа по UNC-шаре `\\svn\svnconf$` с правами только у группы админов: блокировка `passwd.lock` (O_EXCL), бэкап `passwd.<дата>`, запись во временный файл → проверка разбора → `os.replace`, строка в `admin_journal.log` (кто, что, без паролей). Сброс пароля генерирует временный пароль и показывает его один раз. Отзыв доступа: удалить из групп authz + удалить строку passwd, и всё это одним действием.
- Роли в UI: «Сотрудник проекта / Утверждающий / Админ» → группы authz. Матрица «проекты × люди» с тремя состояниями: нет / читает и ведёт версии / утверждает.

## 4. Упрощения UX

**Один главный экран «Мой проект»** (новая первая вкладка вместо «Скачать проект»):
1. Поле «Путь к проекту на Z: или ссылка», рядом недавние и избранное (уже есть).
2. Под ним одна строка состояния и **одна большая кнопка**. Её смысл выбирает программа:
   - проект не скачан → «Начать работу»;
   - скачан, на сервере свежее → «Получить свежее»;
   - есть мои правки → «Сохранить на сервер»;
   - всё сохранено в моей версии → «Отправить на утверждение»;
   - отправлено → «Ждёт утверждения у Петрова (2 дня)», кнопка неактивна;
   - возвращено → «Петров вернул: <комментарий>», кнопка «Продолжить работу»;
   - сломано → «Починить папку».
3. Список «Мои чертежи»: занятые мной, изменённые, чужие замки, с кнопками «Занять» / «Освободить».
4. «Ещё ▾»: Открыть папку, История (TortoiseSVN), Отменить мои правки, Перейти на другую версию, Выпуски, Окна TortoiseSVN для опытных.

**Убрать с глаз обычного пользователя**: вкладку «Ветки и версии» (оставить утверждающим под именем «Версии проекта»), «Создать ветку» (ветка создаётся сама при «Начать работу»), «Merge», «Зафиксировать версию» (только утверждающим как «Сделать выпуск»), выбор «Что скачать», «Починить (Clean up)» как постоянную кнопку, номер ревизии.

**Вкладка «Мои проекты»** остаётся списком всех копий, но с той же колонкой «Что сделать» и той же большой кнопкой для выбранной строки.

**Вкладка «На утверждение»** видна только группе утверждающих (членство проверяется чтением `admin/roles.json` или пробой прав).

**Защита от «сломал»**: каждое разрушительное действие показывает, что именно произойдёт и как это отменить; «Отменить мои правки» сначала копирует файлы в `%APPDATA%\SvnHelper\backup\<дата>`; при закрытии программы с несохранёнными правками появляется вопрос; любая ошибка ведёт к одному следующему шагу и кнопке «Скопировать отчёт для администратора» (уже есть).

## 5. Этапы реализации

### Task 0.1 — Проверки до кода
**Level:** Middle+ · **Assignee:** сисадмин + teamlead · **Goal:** снять три блокирующих риска. **Files:** нет (протокол в `workspace/dev/` или в TODO.md).
**Steps:** 1. Сборка Компас из Z: → checkout в `C:\Проекты_svn` → открывается ли без потери ссылок; то же в папке `…__ветка`. 2. Наличие `svnmucc.exe` в TortoiseSVN bin и на сервере. 3. ОС сервера, домен, лицензия VisualSVN.
**Acceptance:** - [ ] письменный ответ по каждому пункту. **Out of scope:** код. **Оценка:** 1 день.

### Task 1.1 — Публикация trunk → Z:
**Level:** Middle+ · **Assignee:** developer + сисадмин · **Goal:** витрина обновляется сама за ≤ 2 мин после принятия. **Files:** `server_hooks/post-commit(.bat)`, `server_hooks/publish_mirror.ps1` (или `.sh`), `server_hooks/README.md`.
**Steps:** 1. post-commit: `svnlook dirs-changed` → флаги проектов с trunk. 2. Воркер с mutex: update → `robocopy /MIR /XD .svn /R:1 /W:1 /NP /LOG+` → маркер-файл; код выхода robocopy ≥ 8 = ошибка → письмо. 3. ACL витрины.
**Acceptance:** - [ ] коммит в trunk появляется на Z: ≤ 2 мин; - [ ] открытый на Z: файл не роняет публикацию, докопируется потом; - [ ] коммит в ветку витрину не трогает; - [ ] обычный пользователь не может записать на Z:\Проекты_SVN. **Out of scope:** публикация веток. **Оценка:** 2 дня.

### Task 1.2 — Хуки прав и межветочных блокировок
**Level:** Senior · **Assignee:** teamlead · **Goal:** сервер сам защищает trunk, чужие ветки и чертежи. **Files:** `server_hooks/pre-commit*`, `server_hooks/pre-lock*`, тесты в `tests/test_real_svn.py` (`SvnserveAuthTests`).
**Steps:** 1. `branches/<логин>_*` пишут автор и `approvers`. 2. pre-lock: тот же относительный путь занят в trunk/другой ветке → отказ с именем, кто занял. 3. Удаление проекта только `admins`.
**Acceptance:** - [ ] тесты на svnserve для каждого правила; - [ ] fail-closed; - [ ] кириллица в путях и сообщениях. **Out of scope:** UI. **Оценка:** 3 дня.

### Task 2.1 — Путь Z: ↔ ссылка
**Level:** Middle · **Assignee:** developer · **Goal:** пользователь вставляет путь с Z: и получает проект. **Files:** `svnhelper/config.py` (`mirrors`), `svnhelper/server.py` (`map_share_path`, `classify_target`), `svnhelper/winutil.py` (UNC), `tests/test_core.py`.
**Steps:** 1. Разбор `mirrors`. 2. Буква → UNC → URL; обратное URL → путь витрины. 3. Состояния: есть проект / нет (вне витрины) / подпапка проекта (поднимаемся до trunk) / нет прав.

## 6. Организационные шаги

- **Владелец сервера**: один названный сисадмин и заместитель. Он отвечает за бэкап, хуки, права, снятие забытых блокировок, письма об ошибках публикации.
- **Пилотный проект**: живой, но не горящий; 3–5 конструкторов; объём ≤ 10 ГБ; есть сборки Компас (проверка ссылок).
- **Правила на Z:**: `Z:\Проекты_SVN` только чтение; старая папка перенесённого проекта переименовывается в `_ПЕРЕНЕСЕНО_…` и закрывается на запись; «правки только через программу».
- **Регламент**: одна задача = одна «моя версия» = свой узел/чертёж; сохранять минимум раз в день; блокировки дольше 3 дней — повод позвонить.
- **Обучение**: 45 минут вживую на пилотном проекте + обновлённая `ШПАРГАЛКА.html` с новыми словами; утверждающим ещё 30 минут.
- **Бэкап**: ночной `svnadmin hotcopy` → другой диск/сервер, хранение 30 дней; ежемесячная тестовая загрузка; бэкап `svnserve.conf`, `passwd`, `authz`, хуков.

Затем обычное скачивание в локальную папку.

- Найдено по пути: `svn import` искажает путь «a @ b» (запуск из самой папки с «.»), не разбирает peg (без «@» в конце), а `svn delete`/`list` с %40 требуют «@» в конце; глоб-шаблоны svn побайтовые (кириллица без классов [аА]); import заходит внутрь junction (исключаем по имени).

**Упрощено**
- Не журнал задачи в `%APPDATA%` (create_jobs), а атомарность двух ревизий и откат в той же операции; сбой самого отката показывается текстом «сообщите администратору».

- Права на создание не проверяются заранее: отказ сервера показывается после попытки (до записи чего-либо).
- Окна сохранения/истории/отката — TortoiseSVN (в них есть английские слова).
