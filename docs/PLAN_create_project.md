# План: «Создать проект из папки», «Отвязать», «Удалить на сервере», правила файлов

Источник: проект решения (Opus, Plan-агент), сверен с кодом `svnhelper/`. Код на момент написания не менялся.

## Главное решение (нужно подтвердить)

Программа сейчас запрещает рабочие копии на сетевых дисках (`checks.check_target`, `NETWORK_MESSAGE`): `.svn/wc.db` это SQLite, на SMB-шаре он портится; `.svn/pristine` удваивает объём; файлы с `svn:needs-lock` у коллег становятся «только для чтения».

Поэтому по умолчанию:
- папка на `Z:` **только читается**, рабочая копия создаётся локально (`work_dir\<имя>`), на `Z:` по желанию кладётся `ПЕРЕНЕСЕНО_В_SVN.txt` со ссылкой;
- режим «сама папка становится рабочей копией» только для локального диска (или по флагу админа `allow_network_wc` в `svn_helper.json`).

## Поток

1. Шаг 1 вкладки «Скачать проект»: ввод локального пути (`X:\…`, `\\…`) больше не ошибка. Проверка `svn info`: уже рабочая копия, либо «не связана с SVN».
2. Ссылка: статус проекта на сервере: есть / нет (кнопка «Создать проект из папки…» активна) / папка без trunk / внутри чужого проекта (отказ) / нет связи или прав.
3. Вкладка «Новый проект» (`gui/create_tab.py`): исходная папка (скан с прогрессом), место и имя на сервере, что положить (дерево, чипы по расширениям, сводка размера), какая рабочая копия после создания, комментарий.
4. «Отвязать» (в «Мои проекты → Ещё») и «Удалить на сервере» (только админы).

## Команды создания (порядок)

Проверки без побочных эффектов: проекта нет, родитель есть, у предков нет `trunk`, `src` не внутри рабочей копии, места ≥ 2,2 × объём.

1. `svn mkdir --parents -m … URL/p/trunk URL/p/branches URL/p/tags` (одна ревизия R1). Ошибка здесь ничего не оставляет.
2. `svn checkout --depth empty URL/p/trunk@ <dest>`.
3. Локальный режим: копируем выбранные файлы из `src` в `dest` по точным путям, junction пропускаем.
4. `svn add --parents --depth empty <пути>` пачками.
5. `svn propset svn:global-ignores …`.
6. `svn commit` со стримом прогресса. Это первый коммит из программы: зафиксировать в README как исключение «первичный импорт».

Журнал задачи в `%APPDATA%\SvnHelper\create_jobs\<id>.json` после каждого шага. Откат: `revert -R`, удаление только созданного нами `.svn`/`dest`, затем `svn rm URL/p` только если HEAD = R1, автор мы, внутри три пустые папки. Отмена во время commit: `cleanup`, сравнить ревизию с R1; если коммит прошёл, доделать `update`, не откатывать.

## Отвязка и удаление

- Отвязать: только корень рабочей копии; `status` с предупреждением о несохранённом; `svn unlock` своих блокировок; `.svn` переименовать в `.svn_отвязано_<дата>` (или в Корзину), не удалять.
- Удалить: `svnmucc -r <REV> rm` (если нет svnmucc, `svn rm` с проверкой HEAD). Подтверждение: размер, автор последней правки, чужие блокировки = отказ, ввод имени проекта, причина, кнопка активна через 3 с. Серверная защита: ветка в `server_hooks/pre-commit` (удаление папки с `trunk` только пользователям из `admins.txt`, fail-closed). Опция «Восстановить удалённый проект».
- Права записи: честной пробы у svn:// нет; идея «зонда» (коммит `SVNLITE-PROBE`, хук всегда отклоняет) проверить тестом на svnserve.

## Правила файлов

Три разных механизма: «Отслеживать» это `add` + `svn:global-ignores`; «Только чтение» это `svn:needs-lock`/`auto-props`; «Скачивать» это личная настройка в `settings.json` по URL. Приоритет: правила администратора (`filter`) > свойства проекта > личные. Честное «не качать вовсе» это `--depth empty` + `update --set-depth`, но глубина «прилипает» (Update не принесёт новые файлы), поэтому на первом этапе оставить «скачать, затем exclude» и пометку «частичная копия».

## Риски и тесты

Кириллица и символы вне cp1251 в `--targets` (идти через argv); длинные пути считать для `dest`; вложенный `.svn`/`_svn`/`.git` в источнике; открытые файлы (`~$*`) предупреждать до старта; несогласованный снимок при изменении `Z:` во время копирования; auto-props needs-lock делают файлы CAD «только для чтения» (напомнить про «Занять файл»); большие объёмы (Z: → ПК → сервер) нужна оценка времени. Тесты: расширить `tests/fake_svn.py` (mkdir/add/commit/propset/rm/revert/cleanup, режимы commit_authz, commit_hang, busy), `test_real_svn.py` на file:///, `SvnserveAuthTests` для authz и хука; сетевой диск вручную (`net use X: \\localhost\C$`).
