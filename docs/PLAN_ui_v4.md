# SVN-lite v4: кнопки по смыслу, «Скачать проект» внутри «Мои проекты», панель подсказок

Дата: 2026-11-03. Статус: **DRAFT**, код не менялся. Основа: замечания владельца по снимку окна (коммит cbb14f5),
`docs/PLAN_v3_ui.md`, `docs/DECISIONS.md` (C.1, C.3, 2026-11-02), код `svnhelper/gui/*`, `tests/test_gui_smoke.py`, `tests/test_ui_texts.py`.

## Цель и мерило

Владелец просит: (1) все кнопки справа, включая шаблоны комментария; (2) слева только выбор проекта и действия над
проектом целиком, остальное по подвкладкам; (3) убрать вкладку окна «Скачать проект» и сделать скачивание внутри
«Мои проекты»; (4) внизу окна панель подсказок, которая сама подсказывает следующее действие; (5) оставить место
под будущий ИИ-чат.
Каждое решение проверяется пятью вопросами: понятно без обучения; мало кликов для частого; кнопка там, куда человек
смотрит, без дублей; одно главное действие на экране; новичок без проектов сразу видит путь к скачиванию.
Если удобство спорит с простотой кода или прежним решением, выбрано удобство, цена названа.

## 2. Новая раскладка

**Слева (с «Проектами»): проект целиком.** Порядок по частоте:
```
[имя проекта]
⟳                              подсказка «Проверить состояние»
[Разобрать конфликт | Починить папку | Восстановить историю]   только когда нужна, подсвечена
Получить новое (N)             проекты с сервера; подсвечена, когда это главное действие
Отправить на сервер… / Продолжить без истории    только проекты без сервера (как сейчас)
Отмена                         только пока идёт получение нового (до U4.5)
—  Открыть папку · Открыть на сервере · Ещё ▾
—  ＋ Новый проект…            обычный стиль
```
«Ещё ▾» не меняется: TortoiseSVN, «Отправить на сервер…», «Удалить прежние сохранения…», «Для опытных».

**Справа (с «Состоянием проекта»): по подвкладке.**

| Подвкладка | Кнопки сверху вниз |
|---|---|
| Изменения | «Сохранить отмеченное» (у проекта с историей на компьютере вместо неё «Сохранить у себя»); — три шаблона; «Последние ▾» (меню из 5 последних комментариев, как `App._menu_button`) |
| Новое | кнопок нет; ярлык со счётчиком «Новое 4» (как «Изменения 3»); подпись «Получить: кнопка «Получить новое» слева» |
| История | кнопок нет |
| Занятые | «Занять файл…», «Освободить…» (выбраны свои строки: освобождает их; ничего не выбрано: окно выбора своих файлов, как прежняя «Освободить файл…»); таблица `selectmode="extended"` |
| Ветки | «Перейти», «Отличия», «Перенести правки…», «Новая ветка…», «Скачать отдельно», «Зафиксировать версию…» |

**Одно главное действие на экране.** В U4.2 `main_action` не меняется (его выравнивает U4.6, раздел 6), меняется
место подсветки: resolve/repair/restore,
update, publish подсвечивают кнопку слева; commit подсвечивает «Сохранить отмеченное» (или «Сохранить у себя»)
справа. Остальные кнопки обычные: «＋ Новый проект…» и «Перейти» теряют постоянную подсветку.
Цена: отмена решения 2026-11-02 «Новый проект подсвечен всегда» (видимость кнопки обеспечена местом и тестом масштаба).

**Меньше кликов без дублей.**
- При смене выбранного проекта (не при автопроверке раз в 5 с): есть конфликт или правки, значит открывается
  «Изменения»; иначе остаётся подвкладка, которую человек выбрал сам. Пока курсор в поле комментария, вкладку не трогаем.
- Двойной щелчок по строке проекта (сейчас не занят) разворачивает «Состояние проекта» на подвкладке главного действия.
  Это путь к сохранению при свёрнутом «Состоянии», где левой «Сохранить на сервер» больше нет.
- Длинный шаблон из общих настроек не раздувает колонку: ширина справа ограничена `px(240)`, текст кнопки
  укорачивается с «…», полный текст во всплывающей подсказке (новая `widgets.fit_text`).

## 3. «Скачать проект» без вкладки окна

**Вариант A (рекомендую): подвкладки «Мои проекты | Скачать проект» в колонке «Проекты».** В колонке 2
`ttk.Notebook` в стиле `Inner.TNotebook`. Привычные слова остаются, но становятся подвкладками. На «Скачать проект»
колонка 2 показывает поиск и дерево сервера (сразу, без «Выбрать из списка ▾»), колонка 3 называется «Скачивание»
(новый `CollapsibleColumn.set_title`) и показывает форму: ссылка или путь (с «Недавние ▾ · ☆ · Выбрать папку на
диске…» у поля), «Что скачать», «Куда» (тот же `dir_var` и список папок), полоса хода. Справа в форме своя
колонка `SideButtons`: «Скачать» (подсвечена), «Создать проект из этой папки…», «Удалить недокачанную папку».
Левая колонка в этом режиме скрыта: в ней только кнопки выбранного своего проекта.
**Вариант B: форма скачивания вместо «Состояния проекта»** по кнопке слева, дерево внутри формы. Дешевле
(примерно половина U4.3), но правая часть показывает не то, что выбрано в списке, а кнопка остаётся дублем.
**Вариант C: отдельное окно «Скачать проект»** (как «Новый проект»). Раскладку не трогает, но окно теряется за
главным, долгое скачивание в немодальном окне легко закрыть, владелец хотел внутри «Мои проекты».

**Как в A не потерять функции вкладки.** Не переписывать, а разрезать `_build_download_tab` на
`_build_server_browser(parent)` (поиск, `ServerTree`, результаты, строка состояния дерева) и

## 5. Панель подсказок внизу окна

**Рекомендация: панель всегда, одна строка, с режимом «подробно».** Одной строки состояния мало: сейчас ход
работы (`mine_status`) виден только в подсказке индикатора в шапке, то есть фактически не виден; «Отмена» прячется
вместе с «Проектами».
1. **Что показывает.** Слева текст: под курсором или в фокусе элемент: что делает и когда нужен («Получить новое:
   принесёт с сервера то, что сохранили коллеги. Ваши правки не пострадают»); у серой кнопки ещё и почему серая
   («Сейчас недоступно: идёт сохранение»). Без наведения: совет об ошибке без окна (15 с), иначе результат действия
   (10 с), иначе проактивная подсказка (раздел 6). Справа: ход долгой операции и «Отмена».
2. **Без дублей.** Карточка «Что сделать: …» говорит *что* (состояние), панель говорит *как* (какую кнопку и где);
   когда карточки не видно (свёрнута, подвкладка «Скачать проект»), панель показывает и то и другое. Результат по
   проекту остаётся в карточке (`note_label`, он помнится по проекту); в панель он попадает, только когда карточки
   не видно, и результаты не по проекту («Скачано…», «Список сервера перечитан»). Ошибки, требующие решения,
   остаются окнами (`show_error`, вопросы), панель их не повторяет; туда идут тихие сбои, которые сейчас уходят в
   `mine_status` («Нужен вход на сервер»). Всплывающие подсказки у кнопок (⟳, `publish_btn`) убираются; остаются
   только для данных: полный путь папки, укороченный шаблон, индикатор связи (в его подсказке только связь).
3. **Размер.** «Вид → Подсказки внизу: подробно (2 строки, по умолчанию) | коротко (1 строка) | только ход работы»
   (`settings.hint_mode`). В режиме «только ход работы» полоса появляется на время операции (как `offline_bar`,
   `_fit_height_for_bar`). Окно ниже `px(700)` всегда даёт одну строку.
4. **«Отмена» и ход.** Для всех долгих операций одно место: правая часть панели («Получаю новое: 120 файлов
   [Отмена]», «Скачиваю…: 45% [Отмена]», «Сохраняю на сервер…» без отмены). `mine_cancel_btn` уходит из левой
   колонки, `cancel_btn` из формы скачивания (полоса хода в форме остаётся). Пока идёт получение, кнопка слева
   «Получаю новое…» серая.
5. **Тексты и механизм.** Модуль `svnhelper/gui/hints.py`: словарь `HINTS: dict[str, tuple[str, str]]` (ключ →
   коротко, подробно), функция `hint(widget, key, reason=None)` и класс `HintBar`. `hint` вешает `<Enter>`,
   `<Leave>`, `<FocusIn>`, `<FocusOut>` с `add="+"` (уживается с `Tooltip`), уход с элемента возвращает фоновый текст
   через 150 мс (без мигания между соседними кнопками). Для строк таблиц `hint_rows(tree, fn)` по `<Motion>` и
   `identify_row`, для ярлыков `hint_tabs(notebook, keys)` по `identify`/`index("@x,y")`, для пунктов меню
   `<<MenuSelect>>`. Панель одна на главное окно, `hints.install(bar)`; без неё (тесты отдельных виджетов,
   диалоги) `hint` ничего не делает. `SideButtons.add` и `ButtonRow.add` получают параметр `hint=`, поэтому
   `ProjectPanel`, `CommitPanel`, `lines_tab`, форма скачивания не пишут обработчиков. `hints.py` добавляется в
   `RU_CHECKED` в `tests/test_ui_texts.py`; тест: у каждой показанной кнопки обеих колонок есть ключ в `HINTS`.
6. **Риски и цена.** Минус 30–46 px высоты при минимуме `px(640)`: проверить `test_buttons_fit_into_window_on_every_tab`
   (780x640, шесть кнопок «Веток»). Масштаб 100–150%: высота строки через `px`, перенос по ширине (`_autowrap`).
   Тёмная тема: только ttk-стили (`App.TFrame`, `Hint.TLabel`), без своих цветов. `<Enter>` приходит и на серые
   ttk-кнопки, проверить на Windows через `event_generate`. Комбобокс и дерево составные: события вешать на сам виджет.
7. **Задача** U4.5, после U4.4 (трогает почти все файлы окна), около 350 строк кода и 150 тестов.

## 6. Проактивные подсказки

Панель сама называет **одно** следующее действие с числами и именами, подсвечивает его кнопку, щелчок по тексту
равен нажатию этой кнопки (решение владельца).
1. **Один источник.** Сейчас логика в трёх местах и уже расходится: «Что сделать» дают `messages.status_line` (с
   поправками `_status_for`/`_state_cells`: версия, незаконченный переход, нет связи) и `localrepo.status_line`;
   подсветку выбирает `projects_tab.main_action`; помощнику `next_action` даёт `ops/projects._next_action`. Проект с
   новым и своими правками: карточка «Сначала «Получить новое»», ops `get_new`, а `main_action` подсвечивает
   сохранение. Предлагаю модуль без tkinter `svnhelper/next_step.py`: `next_step(facts) -> NextStep(code, button,
   priority, data)`; `facts`: состояние, `WcStatus`, версия, история на компьютере, нет связи, папка занята, вход.
   Из него берутся подсветка (`main_action` становится обёрткой), строка «Что сделать» карточки и таблицы и
   подсказка панели. `ops._next_action` переходит на тот же `next_step` через таблицу кодов; коды ops (`get_new`,
   `save`, `take_lock`, …) не меняются. Для «новое и правки» один порядок: сначала «Получить новое» (как карточка и
   ops). Цена: правка `MainActionTests`.
2. **Приоритет: одна подсказка.** Сначала выбранный проект; если у него всё в порядке, самый важный из остальных
   («В проекте «сушилки» конфликт»). Порядок: вход не выполнен (`_auto_auth_failed`) → папка проектов не найдена →
   конфликт → папка повреждена, незаконченный переход, пропала история → новое у коллег → свои правки (в том числе
   «файл изменён, но не занят») → файл, нужный мне, занят другим → проект только на компьютере. Молчит: нет связи
   (говорит `offline_bar`), давно занятые свои файлы (говорит `lock_warn`), идёт операция (говорит правая часть).
   Всё в порядке: «Всё сохранено и получено» в режиме «подробно», пусто в «коротко». «Вы давно не получали новое» в
   v4 не делается: время последнего получения нигде не хранится, а при связи новое видно по проверке раз в 5 с.
3. **Кнопка и щелчок.** Подсвечивается та же кнопка, что главная (`Accent.TButton`, без второй рамки: одна
   подсветка на экране). Для другого проекта кнопка не подсвечивается, щелчок выбирает проект.
   **Правило безопасности.** Щелчок по подсказке вызывает `invoke()` подсвеченной кнопки, то есть тот же обработчик
   с теми же проверками и окнами; серая кнопка не срабатывает. Если обработчик сам пишет на диск или на сервер без
   своего окна подтверждения или действие необратимо, щелчок только переводит фокус на кнопку (и открывает её
   подвкладку), действие делает человек. Флаг `click` хранится в словаре рядом с текстом.

| Код | Пример текста | Кнопка | Щелчок |
|---|---|---|---|
| login | «Вы не вошли на сервер: проекты не проверяются» | имя в шапке | окно входа |
| no_folder | «Папка C:\Проекты не найдена» | «Выбрать…» | окно выбора папки |
| conflict | «Конфликт в Рама.cdw: ваши и чужие правки» | «Разобрать конфликт» | нажать (окно выбора) |
| broken, history | «Папка повреждена» / «История найдена в другом месте» | «Починить папку» / «Восстановить историю» | фокус (работают без окна) |
| get_new | «У коллег новое: 3 файла (Иванов). Нажмите «Получить новое»» | «Получить новое» | фокус (пишет на диск без окна) |
| save | «Не сохранено 3 файла: напишите, что сделали, и сохраните» | «Сохранить отмеченное» | открыть «Изменения», курсор в поле |
| need_lock | «Рама.cdw изменён, но не занят: займите его» | «Занять файл…» | открыть «Занятые» и нажать (окно выбора) |
| locked_other | «Рама.cdw занят Ивановым с 10:20: попросите освободить» | нет | открыть «Занятые» |
| publish | «Проект только на этом компьютере» | «Отправить на сервер…» | нажать (окно) |
| other | «В проекте «сушилки» конфликт» | нет | выбрать проект |

4. **Не раздражать.** Текст меняется только при смене состояния, не чаще раза в 2 с, без мигания и окон. Крестик
   «Скрыть» убирает подсказку этого вида для проекта до смены её подписи (код и числа, как `Notice.signature`).
   С треем дублей нет: `notify_ui._window_active()` уже не показывает окошки, пока окно на экране и в фокусе;
   панель работает только в окне, окошки только вне его, `notifier.py` не меняется.
5. **Наведение важнее на время.** Пока курсор или фокус на элементе, видно его пояснение; через 150 мс после ухода
   снова проактивная. Порядок: пояснение элемента → совет об ошибке → результат → проактивная.
6. **Тексты.** `hints.NEXT_STEP_TEXTS[code]`: подробный и короткий текст с полями `{files}`, `{who}`, `{when}`,
   `{project}`; числа через `messages.files_count`/`plural`. Короткий текст заменяет строки «Что сделать» в
   `messages.status_line`, чтобы карточка, таблица и панель говорили одно. Проверяет `test_ui_texts`.
7. **Тесты.** Таблица «факты → код, текст, кнопка, щелчок» для `next_step` без Tk. В окне для каждого кода
   подсвечена ровно эта кнопка; щелчок по тексту панели (`event_generate("<Button-1>")`) вызывает тот же обработчик,
   что кнопка (`mock.patch.object` на обработчик, вызван один раз); для кодов «фокус» обработчик не вызван, фокус на
   кнопке; при серой кнопке ничего не вызвано. Тесты `next_action` в ops проходят без изменений.

## 7. Задел под ИИ-чат (не проектируем)

Уже есть: слой `svnhelper/ops/` (реестр `registry.py`, описания и живые фразы `texts.OPERATIONS[...]["examples_ru"]`),
политика `agent_policy.py` (по умолчанию только чтение, потолок `agent_max_mode`), запись в два шага `*_plan`/`*_apply`,

`PLAN_project_memory.md` (обсуждения как данные для помощника, вопрос о допустимых моделях).
**Где жить чату.** (а) Нижняя панель с ярлыками «Подсказки | Помощник», которая по «Помощнику» выдвигается вверх
(рекомендую: то же место и словарь, контекст выбранного проекта под рукой); (б) выдвижная колонка справа: ширины уже
не хватает (минимум 900, пять колонок); (в) отдельное окно: запасной путь для маленьких экранов.
Чтобы v4 не переделывать: `HintBar` делается рамкой с местом под ряд ярлыков и пакуется `side="bottom"` до основной
области, чтобы выдвижная часть встала между ними.
**Решить до чата:** какая модель и где работает (внешний сервис или своя на сервере); где ключ (лучше посредник на
сервере, а не ключ на каждом ПК; иначе DPAPI, как пароль); что можно отдавать модели (чертежи, комментарии,
обсуждения; метка «закрытый проект»); помощник ходит только через `ops` и `agent_policy`, запись только `*_apply`
после явного «Да» человека в чате, всё в журнал; поведение без связи; лимиты и цена.
**Пригодится из панели подсказок:** место в окне, словарь `HINTS` (помощник объясняет кнопки теми же словами),
«что делать дальше» как контекст, `examples_ru` как готовые вопросы-подсказки.

## 8. Риски

- **Ширина.** Минимум окна `px(900)`: слева ~230, «Проекты» 260 (340 на «Скачать проект»), справа до 240; при
  минимуме сжимается «Состояние» (таблицы листаются). На «Скачать проект» левая колонка скрыта, это отдаёт ~240 px.
- **Масштаб 100–150%.** Ярлыки «Мои проекты | Скачать проект» в колонке 260 px: тест `reqwidth` блокнота колонки 2
  не больше ширины колонки при 1.0/1.25/1.5; правые кнопки не обрезаны (`test_side_buttons_fit_at_every_scale`).
- **Тёмная тема.** Заголовок свёрнутой колонки рисуется на Canvas: после `set_title` вызвать `redraw()`.
- **Свёрнутые панели.** «Проекты» свёрнуты: нет левой колонки и подвкладки «Скачать проект», путь через полосу
  «Проекты» (первый запуск разворачивает её сам). «Состояние» свёрнуто: сохранение через двойной щелчок по строке.
  Вход в «Скачать проект» разворачивает колонку 3, это запоминается (`<<ColumnToggled>>`), как сейчас.
- **Авто-вкладка** может удивить: срабатывает только при смене проекта, не во время ввода комментария.
- **«Сохранить у себя» вместо «Сохранить отмеченное»** у проекта с историей на компьютере: выборочное сохранение
  у таких проектов пропадает (сохраняются все правки). Цена принята ради одной кнопки сохранения.
- **Скачивание в фоне** при переходе на «Мои проекты»: ход в панели и на ярлыке; закрытие окна спрашивает (как сейчас).
- **Тесты.** ~25 тестов окна переписываются (список в разделе 3), это не дефект, а смена договорённостей.

### Task U4.8 - Колонки кнопок: «с подписями» и «только значки»
**Уровень:** M / Senior (Opus) · **Исполнитель:** teamlead · **Зависимости:** U4.5 (панель подсказок, `hint=` у всех кнопок)
**Цель:** у каждой колонки кнопок (левая `actions_row`; правая `ProjectPanel.side` по подвкладкам; форма «Скачивание») два вида: развёрнутая (иконка над подписью в две строки, кнопка заметно уже нынешней `px(240)`) и компактная (квадратная кнопка только со значком, пояснение даёт панель подсказок и всплывающая подсказка). Прежнее полное сворачивание колонки (`CollapsibleColumn`) остаётся третьим уровнем.
**Решения (не переспрашивать):**
1. Растянуть шрифт по одной оси Tk не умеет: «уже и выше» делается переносом подписи на две строки по словам (`wraplength`) и `compound="top"` (значок сверху). Узкий шрифт (Bahnschrift Condensed) не использовать.
2. Значки: символы шрифта Windows `Segoe MDL2 Assets` (запасной `Segoe UI Symbol`; если нет ни того, ни другого - первая буква подписи в кружке/рамке или просто подпись), словарь `ICONS: ключ подсказки (hints.HINTS) -> символ` в новом `svnhelper/gui/icons.py`. Картинок в exe не добавлять. Шрифт значка масштабируется через `px` вместе с экраном.
3. Переключатель вида: маленькая кнопка-стрелка в верху каждой колонки кнопок («⟨⟨» / «⟩⟩» с подсказкой «Свернуть до значков» / «Показать подписи») плюс пункт меню «Вид → Кнопки: с подписями | только значки» (применяется к обеим колонкам). Состояние колонок хранится в `settings.json` (`buttons_compact_left`, `buttons_compact_right`, по умолчанию False, неверное значение заменяется значением по умолчанию, как у `hint_mode`).
4. Подпись кнопки остаётся её `text` (тесты и доступность), в компактном виде `compound="image"`/значок как текст кнопки с отдельным шрифтом - выбери вариант, при котором `cget("text")` продолжает отдавать подпись; полная подпись всегда в подсказке (`Tooltip` в компактном виде включён и при `hint_mode = progress`).
5. Главная кнопка остаётся единственной подсветкой `Accent.TButton` в обоих видах. «Получить новое (N)» в компактном виде показывает значок со счётчиком (число рядом/поверх значка), чтобы новое не терялось.
6. Ширины: колонка в развёрнутом виде - по самой длинной подписи в две строки (ориентир `px(130)`-`px(150)`), в компактном - `px(44)`-`px(52)`; перерасчёт при смене масштаба и вида. Высота кнопки растёт сама.
**Файлы:** `svnhelper/gui/icons.py` (новый), `svnhelper/gui/widgets.py` (`SideButtons`: режим, ширина, значки, переключатель), `svnhelper/gui/projects_tab.py` (левая колонка, `_layout_mine_columns`), `svnhelper/gui/project_panel.py`, `svnhelper/gui/commit_panel.py`, `svnhelper/gui/download_tab.py`, `svnhelper/gui/lines_tab.py` (только если нужно), `svnhelper/gui/app.py` (меню «Вид»), `svnhelper/gui/hints.py` (причины серых кнопок остаются), `svnhelper/config.py`, `svnhelper/theme.py`, `tests/test_gui_smoke.py`, `tests/test_ui_texts.py`, `tests/test_config_store.py`.
**Критерии приёмки:** - [ ] У каждой показанной кнопки обеих колонок и формы скачивания есть значок в `ICONS` (тест по аналогии с тестом ключей `HINTS`). - [ ] В обоих видах на экране ровно одна `Accent.TButton`. - [ ] Все кнопки помещаются в окно 780x640 на каждой подвкладке (`test_buttons_fit_into_window_on_every_tab` и тест масштабов 1.0/1.25/1.5) в обоих видах; в компактном видимо уменьшается ширина колонок. - [ ] `<Enter>` на компактной кнопке даёт в панели её подробное пояснение, всплывающая подсказка с подписью есть. - [ ] Переключатель и меню «Вид» работают, состояние сохраняется и читается при старте, оба вида строятся в тёмной теме. - [ ] Счётчик «Получить новое (N)» виден в компактном виде. - [ ] Тест слов svn проходит.
